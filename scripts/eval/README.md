# scripts/eval — прогон собранного архива против настоящей модели

Средство измерения шлюза C (решаемость). До него ни один эксперимент проекта не
вызывал настоящую модель: E001–E004 запускали архив без endpoint, E005–E007 — против
скриптованной заглушки, E008 проверял сами фикстуры, а не агента.

Ничто отсюда не импортируется из `agent/` и не попадает в submission.

## Что воспроизводит контракт

| Свойство | Откуда взято |
|---|---|
| cwd агента — `/opt/harbor/local-agent`, а не каталог задачи | `docs/research/harbor-launch-contract.md`, `agent/agent.py:60–68` upstream |
| передаются ровно три переменные: `LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY` | там же; таймаут задачи runner не передаёт никому |
| образ, `WORKDIR`, сервис-entrypoint, cpu/memory берутся из самого пакета | `environment/Dockerfile` и `task.toml` каждой задачи |
| результат читается верификатором задачи из `/logs/verifier/reward.txt` | `tests/test.sh` каждой задачи |
| архив распаковывается `unzip`, а не `python3 -m zipfile` | открытый вопрос организаторам про exec-бит (`HANDOFF.md`) |

Таймаут задачи навязывается снаружи (`timeout` внутри контейнера), как это делает
Harbor через `asyncio.wait_for`. `AGENT_TIMEOUT_S` при `--timeout-scale 1.0`
**не передаётся** — агент живёт на своём внутреннем дедлайне ровно так же, как на
оценке.

## Сеть

Сеть `sber-eval` создаётся `--internal`: у контейнера задачи нет маршрута наружу и
есть ровно один достижимый адрес — контейнер модели. Это то же свойство, что у
оценочного контура. Модель поднимается контейнером, а не берётся с хоста, потому что
хостовый firewall (ufw) отбрасывает трафик docker-мостов к хосту, а два очевидных
обхода хуже: перепривязка хостовой службы на `0.0.0.0` — правка системной службы вне
репозитория, `--network host` для задач — сервисы задач начинают занимать порты хоста
и сталкиваться между повторами.

## Запуск

```sh
sh scripts/eval/start_model.sh                       # эндпоинт в изолированной сети
python3 scripts/build_submission.py
python3 scripts/eval/run_suite.py \
    --model qwen2.5-coder:latest \
    --base-url http://sber-model:11434/v1 --api-key ollama \
    --label E011-baseline --out build/eval-E011
```

Полезные ключи: `--only <задача>…`, `--repeats N`, `--timeout-scale F`.

`--timeout-scale` отделяет «агент не додумался» от «железо не успело»: на CPU 7B даёт
~6 токенов/с, то есть 10–25 с на шаг. Прогон со scale > 1 — **отдельное** измерение с
отдельной меткой, его числа нельзя смешивать с контрактными.

`endpoint_proxy.py` нужен только если модель всё-таки живёт на хосте: он переносит
порт с loopback на адрес моста. В штатной схеме (`start_model.sh`) он не участвует.
