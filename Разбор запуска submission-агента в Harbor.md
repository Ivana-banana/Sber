# Разбор запуска submission-агента в Harbor

**Проверенные исходники.** Harbor исследован в теге **`v0.16.1`**, который в клоне разрешается в commit **`137c27874df6163309c6c0cb218a56a7b0e00e79`**. Это соответствует официальному релизу GitHub и публикации `harbor==0.16.1` на PyPI.[1] [2] Публичный комплект организаторов исследован ровно в commit **`71f90810d7a608677bbcf44f409f0aefded38340`**. Все нижеуказанные ссылки на код закреплены этими immutable commit SHA.

> **Ключевое разграничение:** Harbor 0.16.1 в проверенном пути не принимает `submission.zip` и не распаковывает его. Он получает уже существующий каталог `agent/`, переносит **содержимое** этого каталога в контейнер и запускает `./run.sh` из заданной рабочей директории. Поэтому код даёт однозначный контракт для *эффективного распакованного payload*, но не доказывает политику внешнего сервиса, который принимает zip и должен превратить его в этот каталог.

## Как запускается агент

1. В обычном одноступенчатом task Harbor сначала готовит окружение и вызывает `agent.setup()`, а затем запускает агентскую фазу с текстом `task.instruction`. Для каждого task из public kit это именно `SingleStepTrial`, потому что в его `task.toml` нет `[[steps]]`; порядок в коде — агент, сбор артефактов, затем verifier.[3] [4]

2. У обёртки организаторов `MyInstalledAgent.install()` локальный источник определён как `Path(__file__).parent`. Он создаёт `/opt/harbor/local-agent`, вызывает `environment.upload_dir(source_dir=local_agent_dir, target_dir=self.REMOTE_DIR)` и затем выполняет `chmod +x /opt/harbor/local-agent/run.sh` от root.[5] В Docker-пути `upload_dir()` делегирует `UnixOps.upload_dir()`, где используется `docker compose cp "{source_dir}/." ...:{target_dir}`. Суффикс `/.` копирует **содержимое** source-каталога, а не сам каталог как дополнительную оболочку.[6]

   > ```python
   > local_agent_dir = Path(__file__).parent
   > await environment.upload_dir(source_dir=local_agent_dir, target_dir=self.REMOTE_DIR)
   > await self.exec_as_root(environment, command=f"chmod +x {self.REMOTE_DIR}/run.sh")
   > ```
   > — `agent/agent.py:33–41`.[5]

3. Декоратор `@with_prompt_template` сначала подставляет шаблон, если он настроен; без шаблона он возвращает исходный instruction. Затем wrapper собирает shell-команду `./run.sh {shlex.quote(instruction)} 2>&1 | tee /logs/agent/local-agent.txt`, передаёт её через `exec_as_agent()` и явно задаёт `cwd="/opt/harbor/local-agent"`.[7] [8] `shlex.quote()` означает, что весь текст задачи передаётся **одним shell-аргументом**, включая пробелы и специальные символы, а не разбивается shell’ом на несколько аргументов.

4. `BaseInstalledAgent._exec()` добавляет `set -o pipefail;` перед командой и считает ненулевой return code ошибкой. Следовательно, ненулевой exit `run.sh` не маскируется успешным exit `tee`; он становится `NonZeroAgentExitCodeError` либо одним из его классифицированных подтипов.[9] Обёртка не использует stdout как ответ на задачу: stdout и stderr объединяются только ради лога `local-agent.txt`.

5. В примере `run.sh` вычисляет `SCRIPT_DIR`, использует текущую директорию как `LOCAL_AGENT_WORKDIR`, если та не была задана, и через `exec` запускает `python3 "$SCRIPT_DIR/local_agent.py" "$PROMPT"`.[10] Так как Harbor уже задал `cwd=/opt/harbor/local-agent`, **CWD процесса `run.sh`, Python и инструментов sample agent — `/opt/harbor/local-agent`**, а не `/app`. Задача решается изменением абсолютных путей `/app/...` или командами, которые модель сама направит туда.

6. После агентской фазы `SingleStepTrial` запускает verifier отдельным методом. Verifier загружает каталог `tests/`, исполняет test script и читает `/logs/verifier/reward.json` либо `/logs/verifier/reward.txt`; текстовый reward парсится как число в поле `{"reward": ...}`.[3] [11] Поэтому успешность сдачи определяется автоматическим verifier и его reward, а не финальным сообщением агента в stdout.

## Публичный комплект: как завершается пример и что проверяют tasks

`sample_submission.zip` содержит именно два файла в **верхнем каталоге**: `sample_submission/run.sh` и `sample_submission/local_agent.py`; их содержимое байт-в-байт совпадает с `agent/run.sh` и `agent/local_agent.py`. Это наблюдение сделано по central directory и `cmp` на commit `71f9081`; в Git-дереве archive доступен как файл.[24] Его `run.sh` запускает Python-агент, а тот вызывает OpenAI-compatible endpoint с тремя env-переменными, исполняет инструменты `bash`, `read_file`, `apply_diff`, `append_file`, и при нормальном завершении печатает финальный текст.[10] [13] Печать текста **не является** проверяемым deliverable: ниже представлены фактические проверяемые состояния.

| Task package | Лимиты из `task.toml` | Как sample agent должен завершить задачу | Что проверяет public test |
|---|---:|---|---|
| `bye-file` | agent 120 s; verifier 120 s | Создать `/app/bye.txt` с единственным содержимым `Bye`. | Наличие файла и `cat /app/bye.txt == "Bye"`; скрипт пишет `1` или `0` в `/logs/verifier/reward.txt`. [25] |
| `hello-file` | agent 120 s; verifier 120 s | Создать `/app/hello.txt` с единственным содержимым `Hello`. | Аналогично: наличие и точное значение `Hello`, затем reward 1/0. [26] |
| `find-sqli-login` | agent 600 s; verifier 120 s | Не менять код; записать `/app/security_report.json` с объектом и непустым `findings`. | Pytest требует JSON-object, `findings` array и минимум один finding, совмещающий сигналы SQLi, login/auth и конкретную деталь bypass/credentials/query. Shell-test транслирует успех pytest в reward. [27] |
| `fix-sqli-login` | agent 600 s; verifier 240 s | Исправить SQLi в login без регрессий. | Verifier пересоздаёт PostgreSQL, запускает `uvicorn`, ждёт `/healthz`, запускает pytest; bypass payloads для `/login` не должны давать 200, а normal login и регрессии должны работать. [28] |
| `fix-sqli-search` | agent 600 s; verifier 240 s | Исправить SQLi search без регрессий. | Тот же verifier flow; union payload не должен вернуть `admin`, пароли или другие данные users table; остаются regression tests. [29] |
| `incident-log-forensics` | agent 600 s; verifier 120 s | Создать `/app/incident_report.txt`: четыре непустые `key=value` строки. | Проверяются форма, ровно 4 строки, затем сортировка и точный `diff` с expected report; order keys не важен, значения важны. [30] |

Во всех шести `task.toml` публичного набора указано `allow_internet = true`; это свойство локального public-набора и не отменяет внешнее условие финального offline run.[17]

## Вердикт по layout архива

> **`run.sh` должен оказаться прямым файлом в корне эффективного payload-каталога, который wrapper видит как `Path(__file__).parent`; для обычного unzip без специального strip это означает `run.sh` в корне zip. Один верхний каталог `sample_submission/` данным кодом не поддержан: launcher всегда ищет `/opt/harbor/local-agent/run.sh`, а перенос копирует `source_dir/.`, не делает `cd` и не ищет вложенный `*/run.sh`.** [5] [6] [8]

Это **не** означает, что можно доказать правила upload-портала по одному Harbor: если внешний (неопубликованный) приёмник перед `agent.py` намеренно снимает единственный верхний каталог или копирует его содержимое в `agent/`, то оба zip-layout дадут одинаковый *эффективный* каталог. Но такого нормализатора нет ни в указанном Harbor path, ни в public kit. Поэтому `sample_submission.zip` с `sample_submission/run.sh` противоречит эффективному launch contract при наивной распаковке; README описывает launch contract словесно, но пример zip не является доказательством поддерживаемого вложенного layout.[24] [31]

## Осталось неизвестным

Код не определяет следующие пункты, и делать из них предположения нельзя.

| Неизвестный факт | Почему он не следует из проверенного кода |
|---|---|
| Точная логика приёма `.zip`: лимит 10 MB, безопасная распаковка, strip верхнего каталога, права после распаковки и сообщение об ошибке. | `MyInstalledAgent.install()` уже получает каталог и вызывает `upload_dir`; в этом пути нет filename, `ZipFile`, `unzip` или upload endpoint для submission.[5] [6] |
| Неизменность wrapper’а, образа и backend’а в закрытой оценке. | Public `agent.py` задаёт конкретный путь и chmod, но организатор может заменить wrapper; закрытый runner и digest образа не входят в commit `71f9081`. |
| Реальный token budget закрытых задач и способ его принудительного применения. | В public task configs есть timeouts, но нет token-budget fields; wrapper не передаёт их агенту. [16] [17] |
| Реальный расход и учёт токенов endpoint при частичном ответе/transport failure. | Sample wrapper не извлекает `usage` из OpenAI/Pydantic AI и не записывает token fields в `AgentContext`; Harbor видит только итоговую метрику, если subclass её заполнит. [8] [19] [20] |
| Конкурсное правило при сочетании `exception_info` и reward=1. | `SingleStepTrial` может сохранить agent error и всё же выполнить verifier. Как внешний competition scorer интерпретирует такую комбинацию, в public kit не реализовано.[3] |
