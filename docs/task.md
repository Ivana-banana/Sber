## Цель

Создать универсального автономного агента по кибербезопасности, который работает
на малой локальной LLM в изолированном контуре и решает практические задачи:

- поиск уязвимостей в коде;
- цифровая форензика;
- исправление security-дефектов в SWE-bench-подобном формате;
- CTF-подобные сценарии.

## Контракт сдачи

- Решение передаётся как `.zip` весом не более 10 МБ.
- В корне архива обязателен исполняемый `run.sh`.
- Runner вызывает `./run.sh "<task instruction>"`.
- `agent.py` с `MyInstalledAgent(BaseInstalledAgent)` является общей Harbor-обёрткой
  и при оценке добавляется/заменяется организаторами.
- Реальная логика агента запускается из `run.sh`; рядом разрешены исходники,
  конфиги и скрипты.
- Во время прогона интернет недоступен и установка зависимостей невозможна.
- Для каждой задачи заданы собственные лимиты по времени и токенам. Сам факт лимитов
  нормативен: у любого цикла обязаны быть budget, stop condition и резерв на проверку.
  Конкретные значения в документах не приведены.
- LLM endpoint передаётся через `LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`,
  `OPENAI_API_KEY`.
- Целевая среда — `secureintelligent/acp`; актуальный публичный README указывает
  Python 3.12, Harbor 0.16.1, распространённые agent SDK и системные CLI.
  Зафиксированный digest, а не tag (проверен 25.08 и повторно 26.08.2026):
  OCI index `sha256:1324d7bb140422a9929f5bc538f55ec0480d2731742effee02bf67604130c8a3`,
  `linux/amd64` `sha256:5a93249d3dfd44dbf2e83806f89ce2662a3e575c8ad0fb5c54feb03ec5626132`,
  `linux/arm64` `sha256:60f32b3e722fcfdd6dc3a5f42f8e2a1860cc5c390583616cbfaa45785bf530a3`.
  Оба тега (`latest`, `harbor-0.16.1`) указывают на этот index и не переназначались
  после 02.07.2026. Значения приведены здесь именно для сверки: без них внешняя
  проверка изменений может опереться только на даты push.

## Оценка

Закрытый набор состоит из 15 независимых задач. Каждая оценивается бинарно:

- `1` — автоматическая проверка подтвердила решение;
- `0` — любой другой исход, включая неверный ответ, crash, exception или timeout.

Отдельно оговорено: агент, которому нужен интернет или который не работает в
окружении `secureintelligent/acp`, оценивается в `0` баллов.

Итоговый балл — доля решённых задач. Ранжирование:

1. больше решённых задач;
2. при равенстве — меньше суммарных input + output LLM-токенов;
3. при равенстве токенов — меньше суммарное время выполнения.

Публичные `local_task/` предназначены только для разработки и проверки формы.
Официальная оценка использует другой закрытый набор.

## Публичный комплект

Источник: <https://github.com/SecureIntelligent/UniversalAgenticCompetitionPublic>

Известная структура:

- `agent/agent.py` — стандартная Harbor-обёртка;
- `agent/run.sh` — entrypoint;
- `agent/local_agent.py` — слабый пример реализации, его можно заменить;
- `sample_submission.zip` — пример структуры;
- `local_task/` — публичные примеры с конфигурацией, окружением, инструкциями,
  тестами и иногда reference solution.

Модель в примере организаторов (проверено 14.09.2026 на том же commit
`b95c62f…`, README не менялся): команда локального запуска эталонного агента —

```sh
uv run harbor run -p local_task --agent-import-path agent.agent:MyInstalledAgent \
  -m qwen/qwen3.6-35b-a3b \
  --ae OPENAI_API_KEY=$OPENAI_API_KEY --ae OPENAI_BASE_URL=https://openrouter.ai/api/v1 -y
```

То есть организаторы отлаживают пример на `qwen3.6-35b-a3b` (MoE, ~3B активных
параметров) через OpenRouter. Ни ТЗ, ни README не ограничивают размер модели и не
называют модель закрытой оценки: она приходит через `LOCAL_AGENT_MODEL`, участник её
не выбирает. Отсюда два следствия: локальные прогоны на 14B и 30B-A3B-классе —
допустимая диагностика, а «рекомендованная 7B» в `TEAMMATE.md` и `HANDOFF.md` —
наша внутренняя точка отсчёта из `docs/research/local-model-baseline.md`, не
требование организаторов.

Проверенный upstream commit:
`b95c62fec81656e338af54045efa688fd4979615` от 26.08.2026. Предыдущая точка —
`71f90810d7a608677bbcf44f409f0aefded38340` от 09.07.2026; между ними ровно один
коммит, см. `docs/research/verdict-upstream-watch-2026-08-26.md`.

Единственное функциональное изменение в этом коммите: verifier
`local_task/incident-log-forensics/tests/test.sh` снимает завершающий `\r` с каждой
строки и сортирует в `LC_ALL=C`, то есть CRLF в `/app/incident_report.txt` перестал
давать `0`. Это **публичная локальная** задача; про закрытый evaluator из этого
ничего не следует, поэтому наше требование к выводу агента прежнее — LF, ровно
четыре строки `key=value`, без пробелов вокруг `=`. Там же добавлен `.gitattributes`
(`*.sh`, `*.txt` → `eol=lf`).

На 24.08.2026 в публичном наборе **шесть оцениваемых task packages**:
`bye-file`, `hello-file`, `find-sqli-login`, `fix-sqli-login`, `fix-sqli-search`,
`incident-log-forensics`. Каталог `insecure-api-app` не имеет `task.toml`: это общий
fixture/generator исходников для SQLi-задач, а не седьмая задача.

В public `task.toml` указано `allow_internet = true`. Это не отменяет нормативное
требование финальной microVM без интернета и означает, что штатный public run сам
по себе не доказывает offline-совместимость.

Обнаружено расхождение упаковочных примеров: README описывает обязательный
`run.sh`, а `sample_submission.zip` содержит верхний каталог `sample_submission/`
с `run.sh` внутри. Нормативный layout нельзя угадывать — требуется Harbor smoke для
обоих вариантов и подтверждение организаторов.

## Неизвестное

Документы не сообщают значения per-task лимитов закрытого набора, нормативную
модель, строгий формат финального ответа и неизменность digest образа. Это открытые
вопросы, а не повод для хардкода. См. `PLAN.md`.

Частично закрыто 25.08.2026: digest образа зафиксирован, лимиты public-задач
измерены, контракт запуска прочитан по коду. Остаётся неизвестным, какой сервер
инференса и какая модель стоят за `OPENAI_BASE_URL` на оценке, и из какого
`Dockerfile` собирается среда закрытых задач.
