## Промпт

Разберись, почему телеметрия `agent phase` не долетает до логов eval-прогонов,
и почини это.

Контекст: в `agent/state.py:288-296` уже реализован `start_phase`/`finish_phase`
для фаз `plan`/`act`/`verify` с длительностью, а `agent/main.py:30-37` подписан
на события через `state.event_sink = emit_phase` и печатает
`agent phase: step=... phase=... duration_s=...` в stdout. Но во всех 18 логах
последнего живого прогона E017 (`build/eval-E017-accepted-control/logs/*.log`)
таких строк **ноль** — `grep -c "agent phase" *.log` даёт 0 везде, включая
задачи с 4–7 реальными шагами, где события точно должны были случиться. Логи
содержат только `agent ready:` / `agent done:`.

`scripts/eval/run_suite.py:344-346` пишет `proc.stdout + proc.stderr` без
усечения — значит либо `event_sink` тихо отключается по пути (в
`state.py:277-280` любое исключение внутри `event_sink` навсегда его глушит:
`self.event_sink = None`, задумано как fail-safe, но без диагностики этот сбой
неотличим от отсутствия сигнала), либо stdout не флашится/не долетает до
`subprocess.run` тем путём, которым сейчас запускается агент внутри контейнера
(`exec_agent`, тот же файл).

Задача:
1. Воспроизведи локально (без реальной модели, `StubLlm` подойдёт) полный
   прогон через `run.sh` с перехватом stdout — убедись, печатает ли
   `agent phase` в принципе на этом пути.
2. Проверь путь `docker exec` / `exec_agent` в `scripts/eval/run_suite.py`:
   не режется/не буферизуется ли stdout между контейнером и `subprocess.run`.
3. Проверь, не проглатывает ли `event_sink` исключение на первом же событии
   (например, из-за состояния stdout в `docker exec` — закрытый pipe, non-blocking
   fd и т.п.).
4. Как только причина ясна — почини её тестом (сначала воспроизводящий тест,
   потом фикс, по `CLAUDE.md`).
5. Не запускай новый прогон на живой модели, пока фикс не подтверждён локально:
   цель — чтобы *следующий* реальный E0xx-прогон уже дал по каждой задаче
   breakdown длительности `plan`/`act`/`verify`, а не только summed_wall_s.
6. Зафиксируй результат в `docs/experiments.md` (это не решаемость задачи, а
   инфраструктурный фикс — классифицируй как отдельную карточку) и перенеси
   строку в `HANDOFF.md` → «Завершено».

Явно НЕ входит в эту сессию: абляции `MAX_STEPS`/`VERIFY_RESERVE_FRACTION`,
батчинг read-only действий, live-оценщик p90-раундов, backend-тюнинг (Ollama —
не наш периметр конфигурации). Эти пункты ждут в
`docs/superpowers/plans/2026-09-03-brainstorm-gaps.md` §6.4–6.5 и требуют
именно этой телеметрии как предпосылки — не делай их вслепую.
