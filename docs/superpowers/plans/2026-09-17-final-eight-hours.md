## Task 2. Проверить остатки и решить, нужен ли ещё код — максимум час, до freeze

**Файлы:** `agent/loop.py`, `agent/state.py`, `agent/llm.py`, `agent/tools.py`;

**Вход:** r2b. **Выход:** подтверждённые результаты и не более одного отдельного
исправления; отсутствие нового изменения — нормальный результат этапа.

| Приоритет | Что и почему | Как подтвердить / когда менять |
|---|---|---|
| P0 | Новый сервис после правки действительно работает: public-grader может сам чинить состояние процесса | Реальный HTTP-сервис: после правки ответ меняется, старый pid не держит порт, сломанный импорт даёт FAIL; проверяющий не перезапускает сервис |
| P0 | Отказ thinking-параметра и переполнение контекста не путаются | 422 с эхом max_tokens не уменьшает thinking-cap; настоящий context overflow включает фокус; строка reasoning не исполняется как tool |
| P1 | Мёртвый сервис после неудачного restart не становится ложным finish | Сценарий: правка → restart FAIL → finish с нерелевантной зелёной проверкой; отдельно законная задача, требующая только изменения кода |
| P1 | Повторный отказ до dispatch не съедает весь budget | Сценарий missing content/invalid finish ×N, затем корректное действие; сравнить со сценарием успешного восстановления после двух ошибок |
| P1 | Shell пишет вне workspace | Повторить `escape` на точном r2b; проверить отдельно допустимые пути, прямо заданные задачей |
| P2 | Повторное переполнение ctx 8k, write_json даёт 45 шагов без улучшения | Детерминированная лента плюс живой диагностический прогон; не увеличивать лимиты и не перенастраивать детекторы по одному extra-нулю |

Особенно проверить существующие тесты

- [ ] Для дополнительного фикса сначала сохранить минимальную падающую

- [ ] Для мёртвого сервиса не вводить глобальное «любой code-fix обязан иметь
  живой процесс»: задачи бывают файловыми, offline и CLI. Связывать наблюдение
  только с конкретной предложенной и выполненной попыткой restart; сохранять
  законный finish задачи, не требующей работающего сервиса.
- [ ] Для повторных отказов не принимать раннюю остановку только ради экономии:
  новый policy должен сохранять эпизод с успешным recovery.
- [ ] Красный тест → минимальная правка → targeted/full pytest → независимое ревью
  → отдельный commit → новый SHA архива и весь gate заново. Если цикл не помещается,
  зафиксировать ограничение, не добавлять недомеренный фикс к сдаче.

Не брать сейчас: новый router, новый exact-file parser, глобальную shell-песочницу,
рефакторинг большой loop.py, RAG/multi-agent runtime, настройку под `file:function`,

зелёным: повторить и явно передать владельцу релиза как неустранённый риск.

## Task 3. Приёмка финального r2b — до двух часов

**Файлы:** `scripts/eval/run_suite.py`, `scripts/eval/replay/`,
`docs/experiments.md`, уникальные каталоги `build/`.
**Вход:** замороженные архивы. **Выход:** eligible/стоимость по каждому эпизоду.

- [ ] Oracle replay — все 18 extra. Для каждого архива отдельный свежий endpoint:
  replay хранит cursor между прогонами; повторное использование даёт ложные нули.
  Перед запуском прочитать `scripts/eval/replay/README.md`. Он проверяет проходимость
  заданной ленты действий, не полноту разрешений для любых правильных решений.
- [ ] Если финальный public уже полный, без ошибок окружения и без нагрузки —
  принять его; иначе public ×3 на тихой машине. Запустить/завершить extra ×3.
- [ ] Не переносить результаты `.early` и r2a на новый SHA.

Команда живого прогона; параметры стенда явно берутся из его конфигурации,
доступность модели/прокси проверяется до запуска. Значения ключей не выводить.

```sh
: "${SBER_EVAL_MODEL:?set the existing stand model id}"
: "${SBER_EVAL_BASE_URL:?set the existing proxy URL}"
: "${SBER_EVAL_PROXY:?set the existing counting proxy container}"
: "${SBER_CANDIDATE_ZIP:?set the absolute path of the frozen archive}"
mkdir -p build
SBER_RUN_OUT=$(mktemp -d "$PWD/build/kt7-public-XXXXXXXX")
python3 scripts/eval/run_suite.py --tasks-root local_task \
  --archive "$SBER_CANDIDATE_ZIP" --model "$SBER_EVAL_MODEL" \
  --base-url "$SBER_EVAL_BASE_URL" --counter-container "$SBER_EVAL_PROXY" \
  --network sber-eval --repeats 3 --timeout-scale 1.0 \
  --reuse-images --idle-wait-max 240 --out "$SBER_RUN_OUT" --label kt7-public-final
```

Команда рассчитана на локальный стенд без секретного API-ключа; для защищённого
endpoint использовать принятую в команде передачу ключа без вывода в журнал.
Для extra: новый output и `--tasks-root local_task_extra/tasks`.
Не использовать устаревший Docker cache: образы должны включать восстановленные улики.

**Критерии, фиксируемые до результатов:** public eligible **18/18**, extra eligible
**не меньше 45/54**, без воспроизводимой потери ранее решаемого семейства; replay
18/18. Первые три контроля `0c96797` — 54/54 public; суммы токенов 1.456/1.699/1.626 М.
Последний предзарегистрированный порог команды — **≤1 698 779 токенов** за public ×3
(в журнале округлён до 1.70 М). Не менять его после просмотра r2b.
Если превышен — r2b не прошёл этот критерий; повтор допустим только при документированной
проблеме среды, одинаково для обеих сторон. Одна стохастическая потеря — основание
для проверки, не доказательство причинности.

Разница 1–2 эпизода, ±17% токенов или отдельный медленный эпизод не доказывают
полезность конкретного фикса. r2b содержит несколько факторов: оценивать кандидат
целиком, не приписывать выигрыш одному из них без абляции.
