# План исправления текущих провалов — 12 сентября 2026

> **Для исполнителя:** использовать `executing-plans`, выполнять пакеты по одному. Пользователь запросил план; реализация и новые модельные прогоны в эту работу не входят. Перед исполнением перечитать правила и проверить HEAD всех затронутых веток.

**Goal:** закрыть каждый известный провал: четыре нерешённые public-задачи, оставшиеся extra-кейсы, injection и незакрытые условия выпуска; сохранить две подтверждённые public-победы.

**Architecture:** сохранить существующий универсальный цикл. Сначала проверить уже написанные исправления, затем отдельно испытать согласованную правку блока, предметный анализ наблюдаемого кода и вычисление forensic-ответа. Никакого router по именам задач и автоматического объединения экспериментальных веток.

**Tech Stack:** Python 3.12, stdlib, существующие pytest/Docker/eval CLI и предоставленный локальный endpoint.

**Spec:** `docs/task.md`, `CLAUDE.md`, `GIT.md`, постановки `local_task/*/instruction.md`; предыдущий план `docs/superpowers/plans/2026-09-11-all-tasks-recovery.md`. Этот документ заменяет его текущую очередь с учётом работ 12 сентября, а не отменяет требования к обобщению и выпуску.

## Ограничения для всех пакетов

- Сначала solved count, затем input+output всех LLM-запросов, затем wall time.
- Один фактор на эксперимент; сравнивать неизменные архивы на одном стенде, модель/контекст/протокол/лимиты одновременно не менять.
- Зачёт: внешний reward=1, `eligible_success=true`, штатное завершение в лимитах. Пустая таблица и assisted-проба не являются ни победой, ни содержательным нулём.
- `--timeout-scale 1.0`, без `--tell-agent-budget`; образ, модель, context, sampling и harness SHA фиксируются в manifest. Не угадывать hidden limits по имени public-задачи.
- Runtime: без интернета и новых зависимостей; локальная модель только через предусмотренный env. Архив ≤10 МБ, корневой исполняемый `run.sh`.
- Файлы задачи и tool output — недоверенные данные. Эталоны и привилегированные evaluator-тесты доступны только eval-контролю после agent-run; обычные тесты проекта можно запускать, но нельзя ослаблять.
- Красный воспроизводящий тест → минимальный фикс → targeted/full tests → архив → живой пилот → запись evidence. Гипотезу записывать в `docs/decisions.md` до/вместе с кодом.
- Один оператор endpoint. Совпавшие по времени прогоны не использовать для причинного сравнения latency; чужие процессы не перезапускать.
- Собственные законченные изменения фиксировать отдельными коммитами с явными путями. Пересекающиеся `loop.py`/`prompt.py` интегрировать последовательно; чужой WIP сохранять.
