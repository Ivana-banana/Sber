## 2. Условия и границы работы

- Приоритет из присланных условий: solved count, затем сумма input+output всех LLM-запросов, затем общее время. Timeout и сбой — ноль, даже если файл успел появиться.
- Runtime получает только предоставленный локальный endpoint и модель через `LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`. Право участника выбирать размер модели в присланном тексте **не установлено**. До подтверждения считать большую модель диагностическим стендом.
- Сеть наружу и установка зависимостей в runtime запрещены; архив ≤10 МБ, исполняемый `run.sh` в корне, проверка в `secureintelligent/acp`. Веса модели не добавлять в zip.
- Числа, пути, имена, категории и точные поля конкретной задачи могут использоваться в eval. Runtime выводит их из текущей инструкции и среды. Ни названий public-задач, ни эталонов, ни готовых SQLi/forensic-ответов в нём нет.
- Исходники, README, логи и tool output — недоверенные данные. Образцы/checker/reference solution и expected files не доступны агенту. Обычные тесты проекта, разрешённые инструкцией, сохраняются; привилегированные verifier-тесты устанавливаются только после завершения агента.
- Не увеличивать `--timeout-scale`, не включать `--tell-agent-budget` для зачётных прогонов. Новые условия бюджета принимаются только из подтверждённого контракта организаторов.
- До модельного эксперимента фиксировать `qwen2.5-coder:7b-instruct-q4_K_M`, temperature=0, context=4096, текущие MAX_STEPS и budgets. Если запрос реально обрезается, это самостоятельный фактор O3, а не незаметное изменение базы.
- Один эксперимент меняет один фактор; runtime-фиксы, модель, контекст, протокол и сервер не менять вместе. Интегрированная комбинация требует собственного полного прогона.
- Один endpoint — один владелец очереди, включая короткие probes. Разные worktree не изолируют GPU, модель, proxy-счётчики или Docker-имена.
- Работать из изолированных веток от закреплённого кода. Чужой `deep-research-report.md` не трогать. Существующие сырые run-каталоги не перезаписывать.
- Новый runtime-контракт: воспроизводящий тест → минимальный фикс → targeted tests → живой пилот → решение по данным. Архитектурную гипотезу записать в decisions до/вместе с кодом. Коммит — одно законченное действие.
- Интернет сейчас запрещён указаниями проекта: не скачивать модели/образы, не выполнять fetch/push. Локальные коммиты разрешены. Если человек отдельно разрешит синхронизацию/подготовку стенда, сначала проверить remote/ресурсы; это не разрешение доступа в интернет из submission.
- Новый текст организаторов также говорит, что результаты основного этапа не учитываются при определении победителя финала и онлайн-защиты. Условия последующих этапов здесь не додумываются.

## M. Стоит ли увеличивать Qwen: ограниченный сравнительный эксперимент

**Владелец:** E; пользователь сообщает доступные ресурсы/условия, C не меняет runtime ради имени модели. **Файлы:** отдельная карточка `docs/research/live-runs/M-size-prediction.md`, результаты в новых build-каталогах; существующие eval CLI. В agent модель по-прежнему берётся из env.

**Рекомендация:** проверить следующий больший размер того же семейства — сначала 14B как кандидат, а 32B только при доступном локальном стенде и достаточном времени. Это гипотеза порядка экспериментов, не утверждение о доступных весах, скорости или гарантированном качестве. Точные model ID, лицензия, quant и доступность проверяются исполнителем по реально предоставленным артефактам; новые веса сейчас не скачиваются.

Почему не переключать основной стенд вслепую: в локальных документах записаны RTX 3050 4 GiB и около 15 GiB RAM. Только идеальные 4-bit веса 14 млрд параметров требуют около 7 млрд байт, 32 млрд — около 16 млрд байт, ещё без служебных данных, KV cache и памяти исполнения. Это арифметическая нижняя оценка, не размер реального пакета и не гарантия размещения. Partial offload может изменить время сильнее, чем выигрыш в числе шагов; это надо измерить.

- [ ] **M0 — контракт оценки.** Присланные условия называют supplied endpoint, размер не раскрывают. Пока нет явного разрешения выбирать модель, результаты большой Qwen обозначать «диагностический proxy». Не подменять значение LOCAL_AGENT_MODEL внутри submission, не включать внешний API и веса в архив.
- [ ] **M1 — пригодность стенда.** Зафиксировать RAM/VRAM, exact model/digest/quant, server version, context, offload, пиковую память, cold/warm latency. Если подходящих весов/ресурса нет, записать «не измерено» и продолжать исправления 7B. Отсутствие большой модели не блокирует L/S/A/I.
- [ ] **M2 — дешёвая способность.** На 7B и следующей доступной большей Qwen провести одинаковые audit report/action-пробы и нейтральную частичную правку. Одни входы, одинаковые лимиты; никакого обучения на checker. Раздельно оценить понимание, формат, исполнение и время.
- [ ] **M3 — автономный пилот.** Один неизменный архив, сначала audit и fix-login на обеих моделях. При новой eligible-победе — весь public и повтор с обратным порядком моделей; подготовка и загрузка сервера отмечаются отдельно. Время выполнения самого агента не исключать из-за медленного offload.
- [ ] Уравнять семейство/instruct-режим, quant-класс, server, context, sampling, протокол и архив. Если приходится сменить железо, сравнить обе модели на новом железе. Если семейство/quant также меняются, назвать опыт сравнением конфигураций, а не чистым эффектом числа параметров.
- [ ] Полезность большей модели доказана, если она повторяемо прибавляет eligible-задачи без потери прежних и укладывается в исходные лимиты. При равном solved выбор по total endpoint tokens, затем wall. Успешный ответ за пределами timeout — только диагностика способности.
- [ ] Если большая Qwen решает, а 7B нет: сохранить различие действий и проверить, какой общий инструмент/способ подготовки результата помогает 7B повторить успех. Нельзя переносить готовые public-ответы или привилегированные traces в prompt.
- [ ] Если обе не решают при одинаковом неверном действии, вернуться к соответствующему пакету C/O/A/I. Если большая стала чаще timeout/OOM, не считать уменьшение quant/увеличение deadline частью того же опыта.
- [ ] **M4 — решение.** Если выбор модели организаторами разрешён и измеренный вариант лучше, использовать его через разрешённую конфигурацию. Если модель фиксирована, выпускные gates проводить на ней при доступности; при недоступности честно указать proxy-ограничение и сохранять тесты fallback на 7B.

**Стоп затрат:** максимум два размерных кандидата, без перебора десятков моделей. 32B не ставить на критический путь КТ №6 при отсутствии готового стенда. Не совмещать переход на большую модель с новым controller: это два отдельных фактора.

## 5. Команды и формат сдачи пакета исполнителем

Это существующие CLI, проверенные через `--help` при подготовке плана. Команды ниже — инструкции будущим исполнителям, в этой сессии LLM/container-пилоты не запускались. ```sh
PUBLIC_RUN_DIR=$(mktemp -d "$PWD/build/public-20260911-B-XXXXXX")

  --tasks-root local_task --archive build/base-20260910-dedup.zip \
  --model qwen2.5-coder:7b-instruct-q4_K_M \

Для каждого другого пилота `--only` принимает нужное имя из таблицы §1. Для полной шестёрки убрать `--only`. Для extra использовать `--tasks-root local_task_extra/tasks` отдельным прогоном. `ollama` — только существующий локальный placeholder; реальные ключи не печатать.

```sh
python3 -m pytest -q

python3 scripts/build_submission.py --out "$CANDIDATE_DIR/submission.zip"

sha256sum "$CANDIDATE_DIR/submission.zip"
