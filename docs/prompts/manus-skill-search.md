# Промпт для Manus: поиск скиллов под хакатон AIRI

Копировать целиком в Manus. Файл держим в репозитории, чтобы результат поиска можно
было сверить с тем, что именно спрашивали.

---

## Задача

Найди и оцени готовые Agent Skills (формат Claude Code / Claude Agent SDK: каталог
с `SKILL.md`, YAML-фронтматтером `name` + `description` и опциональными
`scripts/`, `references/`, `assets/`), которые реально помогут команде из 4 человек
выиграть хакатон по автономному ИБ-агенту. Верни отчёт, а не список ссылок.

## Контекст соревнования

Мы делаем универсального автономного агента по кибербезопасности для закрытого
бенчмарка AIRI. Классы задач: поиск уязвимостей в коде, исправление
security-дефектов в SWE-bench-подобном формате, цифровая форензика по логам,
CTF-подобные сценарии с локальным сервисом.

Жёсткие ограничения сдачи:

- сдаётся `.zip` ≤ 10 МБ, в корне исполняемый `run.sh`, вызывается как
  `./run.sh "<текст задачи>"`;
- прогон идёт в изолированной microVM на образе `secureintelligent/acp`,
  Python 3.12, **интернета нет, установка зависимостей во время прогона
  невозможна**;
- LLM — **малая локальная модель** за OpenAI-совместимым endpoint
  (`LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`). Это не Claude и не
  GPT-4-класс;
- 15 закрытых задач, каждая даёт 1 или 0 по автоматической проверке;
- ранжирование: больше решённых задач → меньше суммарных input+output токенов →
  меньше времени.

## Ключевое различие, которое нужно удержать в отчёте

Раздели находки на **две несмешиваемые категории**:

**A. Скиллы для нашего процесса разработки.** Работают у нас на ноутбуках в Claude
Code / Codex, помогают быстрее и надёжнее строить агента. В сдаваемый архив не
попадают вообще. Здесь формат `SKILL.md` берётся как есть.

**B. Доменные знания для встраивания в самого агента.** Наш агент работает на малой
модели офлайн и **не умеет** исполнять Claude Skills — ни прогрессивного раскрытия,
ни загрузки файлов по требованию у него не будет. Поэтому отсюда мы забираем не
механику, а **содержание**: чеклисты аудита кода, порядок работы с SQLi, приёмы
разбора логов инцидента, типовые шаги CTF, — которые мы дистиллируем в компактные
текстовые playbook'и внутри системного промпта. Для этой категории отдельно оцени:
сколько токенов занимает полезная выжимка и можно ли ужать её до 15–40 строк.

Если находка не проходит ни в A, ни в B — не включай её.

## Слоты, которые мы реально хотим закрыть

Категория A:

1. упаковка и предполётная проверка артефакта сдачи (архив, права на файл,
   структура корня, размер, проверка распакованной копии, а не исходников);
2. запуск и валидация решения в чистом контейнере / офлайн-режиме;
3. дисциплина экспериментов: журнал прогонов, воспроизводимость по seed, сравнение
   вариантов изменением одного фактора, классификация провалов;
4. ревью изменения против списка проектных запретов, а не «общая чистота кода»;
5. оценка и отладка agent loop: бюджеты, stop conditions, наблюдаемость трассы,
   поиск причин зависаний и таймаутов;
6. работа с OpenAI-совместимыми endpoint'ами малых моделей: деградация протокола
   (native tool calls → JSON schema → JSON object → текст), устойчивый парсинг
   кривого вывода, конечные retry;
7. сокращение токенов без потери качества, измеряемое абляциями.

Категория B:

8. аудит исходников на уязвимости (в первую очередь инъекции, аутентификация,
   работа с секретами) — как порядок действий, а не как список CWE;
9. минимальный безопасный фикс дефекта с сохранением тестов: воспроизвести →
   локализовать → починить первопричину → проверить, не ослабляя проверку;
10. форензика по логам и артефактам: таймлайн, IOC, корреляция, формат ответа;
11. CTF-подход к локальному сервису: инвентаризация, поверхность атаки, дешёвые
    гипотезы вперёд дорогих.

## Фильтры отсева

Отбрасывай сразу и не упоминай:

- всё про веб-фронтенд, игры, анимации, дизайн, презентации, маркетинг;
- скиллы, чья польза целиком в вызове внешнего API или сети (у агента её нет);
- обёртки над платными SaaS;
- скиллы без лицензии или с лицензией, запрещающей коммерческое использование
  и производные работы;
- «списки промптов» без структуры `SKILL.md`, если только содержание не попадает
  в категорию B само по себе;
- репозитории без коммитов за последние 12 месяцев, если только содержание не
  ценно вне зависимости от свежести (тогда пометь это явно).

## Где искать (отправные точки, каждую проверь на существование)

- официальный репозиторий скиллов Anthropic;
- каталоги и агрегаторы Claude Code skills / plugins / marketplace;
- подборки awesome-claude-code и производные;
- популярные наборы subagent'ов и skills от независимых авторов;
- security-ориентированные наборы для pentest/CTF/SAST-агентов;
- репозитории агентных бенчмарков (SWE-bench, CyberSecEval, CTF-агенты) — там
  часто лежат готовые системные промпты и ACI-описания, годные для категории B.

Не ограничивайся этим списком и не доверяй ему: если репозитория не существует или
он не про то — так и напиши.

## Формат ответа

Две таблицы, A и B, каждая строка — одна находка:

| Название | Ссылка | Последний коммит | Звёзды | Лицензия | Что делает | Какой наш слот закрывает | Что придётся переписать | Риск |

После таблиц:

1. **Топ-5 с обоснованием** — что внедрять первым и почему именно это, с оценкой
   «сколько часов на адаптацию» и «что конкретно улучшится: решённые задачи,
   токены или время».
2. **Чего не нашлось** — слоты из списка выше, под которые готового нет; для них
   набросай, из чего собирать своё.
3. **Прямые цитаты** для категории B: выпиши самые ценные куски текста (чеклисты,
   порядок шагов), чтобы мы могли сразу оценить их на сжатие в playbook.

## Правила достоверности

- Каждое утверждение о репозитории подкрепляй ссылкой. Не существует ссылки —
  не пиши утверждение.
- Не выдумывай названия, звёзды, даты и лицензии. Неизвестно — так и пиши
  «не проверено».
- Не пересказывай README целиком; нас интересует, что мы возьмём и что выкинем.
- Если считаешь, что под какой-то слот готовые скиллы принципиально бесполезны —
  скажи это прямо, это ценный ответ.
