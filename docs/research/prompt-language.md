# Язык резидентного prompt: что стоит перевод на английский

Дата: 04.09.2026. Измерение локальное и воспроизводимое, прогона против модели ещё
не было — он записан как E042.

## Зачем

Резидентная часть prompt (скелет + один playbook + метки блоков) уходит в запрос на
**каждом** вызове. Токены — второй критерий ранжирования после решаемости, а язык
резидента — единственный фактор, который меняет цену этих токенов, не трогая смысл.

Отдельно и не менее важно: публичные задания написаны **по-английски**
(`local_task_extra/tasks/*/instruction.md`). Русский контракт перед английской задачей
заставлял модель читать два языка сразу. Перевод убирает смешение, а не создаёт его.

## Чем меряли

Токенизатор `Qwen/Qwen2.5-VL-7B-Instruct` из локального кэша HuggingFace: его
текстовый словарь — это словарь Qwen2.5, а оценочная модель — `qwen2.5-coder:7b`.

```sh
python3 - <<'PY'
import sys; sys.path.insert(0,'.')
from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-VL-7B-Instruct", local_files_only=True)
from agent.prompt import SYSTEM_SKELETON
from agent import playbooks as pb
print(len(tok.encode(SYSTEM_SKELETON)))
for p in pb.PLAYBOOKS:
    print(p.name, len(tok.encode(p.body)))
PY
```

**Оговорка.** Это заменитель, а не сам endpoint. Прежнее измерение «362 токена скелета»
сделано против модели и включает обёртку chat-шаблона; здесь тот же русский скелет даёт
341. Расхождение в 21 токен — цена обёртки и различие сборок токенизатора. Для дельты
RU→EN это неважно, для абсолютных чисел — важно, поэтому абсолютные значения надо
подтвердить по `prompt_tokens` с endpoint, когда стенд освободится.

**Поправка к переданной оценке.** В `next-session-e040.md` записано «skeleton 362 → 254,
playbook'и дадут ещё ~85, итого ~190». Первое число подтверждается по дельте, но
«~85 с playbook'ов» верно только для `general`: четыре текста из пяти пришли из M4
наполовину английскими, и перевод снимает с них 17–41 токен, а не 85.

Реальная экономия резидента на вызов, если прогнать классификатор по восемнадцати
публичным заданиям (`general` 7, `code-fix` 4, `ctf` 3, `code-audit` 3, `forensics` 1):

    минимум 124, максимум 197, среднее 155 токенов на вызов

При 1243–1293 токенах на вызов (E039, E040) это **около 12%** резидентной стоимости.
На прогоне из 145 вызовов — порядка 22 000 токенов.

## Чего этот перевод не даст

**Секунд — скорее всего почти нет.** Резидентный блок это общий префикс, а он
переживает работу задачи и соседние задачи: `bench_prefix.py` даёт `worked` 4.2 с,
`adjacent` 4.4 с против `cold` 12.2 с. Значит эти 155 токенов чаще всего уже в кэше
сервера, и экономия проявляется как **токены**, которые считаются на каждом вызове
независимо от кэша, а не как время. Оценка «≈5.6 с на задачу» из переданного промпта
исходит из того, что резидент перечитывается каждой задачей заново, а замер префикса
говорит обратное.

**Качества вызова инструментов — не обещано.** Фактор 9 в
`docs/research/system-prompt-evidence.md` закрыт как «не установлено» для tool calling
на открытых 7B–32B, и в списке утверждений без статуса результата прямо стоит
«английский всегда лучше русского для tool calls». Поэтому перевод идёт абляцией с
gate по решаемости, а не уборкой.

## Побочное наблюдение, в область этой задачи не входящее

Классификатор на публичном наборе ошибается заметно: `fix-cache-key-scope` уходит в
`forensics`, а `forensics-sharded-exfil` и `forensics-webshell-chain` — в `code-audit`.
Семь задач из восемнадцати попадают в `general`, то есть на fallback. Это отдельный
фактор и отдельная абляция; здесь записано только чтобы не потерялось.

## Что осталось незамеренным

- абсолютные значения по `prompt_tokens` самого endpoint;
- влияние на решаемость — это и есть E042;
- цена смешения языков отдельно от цены токенов: перевод меняет обе величины сразу,
  разделить их одним прогоном нельзя.
