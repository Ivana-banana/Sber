# Стенд RTX 4080 (16 ГБ) — выбор модели/кванта под thinking-класс организатора (16.09.2026)

Зачем: организатор оценивает на `qwen/qwen3.6-35b-a3b` (thinking, MoE A3B) через
OpenRouter — скорость их эндпоинта неизвестна, но заведомо не 60 ток/с. На нашей карте
`qwen3:30b-a3b` Q4_K_M (17,3 ГБ весов) не помещается: 39 %/61 % CPU/GPU и ~60 ток/с, и
именно скорость генерации thinking упирала агента в 90/120-с таймауты (карточка
`F4-30b-paired`). Задача листа S1: найти конфигурацию, которая (1) того же семейства и
класса, (2) целиком на GPU, (3) заметно быстрее, и задокументировать её как стенд для
дальнейших замеров. Замеры — `scripts/eval/bench_tps.py` (ollama native API, prefill ≈ 4,2k
токенов, генерация 512, температура 0, 3 прогона; первый включает загрузку).

Машина: RTX 4080 16 ГБ (≈2,7 ГБ занято рабочим столом), 24 потока CPU, 31 ГБ RAM,
ollama 0.34.0 в контейнере (`scripts/eval/start_model.sh`), модели в `~/.ollama/models`.

Наблюдения по ходу:
- (b) KV q8_0 + flash-attention на 30B Q4 не ускоряет генерацию: узкое место — эксперты,
  оставшиеся в RAM, а не KV. Prefill +12 %.
- Замер (a)/(b) частично шёл при постороннем потребителе стенда (дубликат-сессия гоняла
  7B через тот же прокси, см. JOURNAL 01:50), отсюда перезагрузки модели между
  прогонами (`load_s` 8–48 с); цифры tok/s внутри прогона от этого не зависят.
- Qwen3.6-35B-A3B в библиотеке ollama есть только от q4_K_M (23–24 ГБ) — на 16 ГБ не
  помещается; кванты ≤ 13,5 ГБ есть у unsloth (UD-Q2_K_XL 12,3 ГБ, UD-IQ3_XXS 13,2 ГБ).
  Скачано через хостовый `ollama serve` на порту 11435 (`OLLAMA_MODELS=~/.ollama/models`),
  контейнер видит модель сразу.

## Решение (16.09 02:25)

Стенд для дальнейших замеров — **конфигурация c**: `hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS`,
`CONTEXT=16384`, `OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0`:

```sh
OLLAMA_FLASH_ATTENTION=1 OLLAMA_KV_CACHE_TYPE=q8_0 CONTEXT=16384 STORE=$HOME/.ollama/models \
  bash scripts/eval/start_model.sh && bash scripts/eval/start_proxy.sh
MODEL='hf.co/unsloth/Qwen3.6-35B-A3B-GGUF:UD-IQ3_XXS'
```

Почему: то же семейство и класс, что у организатора (Qwen3.6-35B-A3B, thinking, MoE A3B);
генерация 118,6 против 63 ток/с и prefill 2490 против 1122 — ровно тот ресурс, которого
не хватало thinking-вызовам (F4-30b-paired). Цена: квант 3 бита (unsloth dynamic) вместо
Q4 — качество рассуждения может быть ниже, чем у организаторского эндпоинта; это
занижает, а не завышает наши оценки solved. 85 % GPU — физический потолок для кванта
≥ 13 ГБ на карте с 2,7 ГБ под рабочим столом; KV-кэш у Qwen3.6 крошечный (170 МБ на
16k), поэтому ctx не является рычагом. Не проверено: UD-Q2_K_XL (12,3 ГБ) поместился бы
на ~93 %, но 2-битный квант рискован для tool-calling JSON.

Правило сопоставимости: все карточки на этом стенде подписываются моделью `q36-iq3xxs`;
сравнивать их с картами на `qwen3:30b-a3b` можно только парно (control/treatment на
одном стенде), не по абсолютным числам.
