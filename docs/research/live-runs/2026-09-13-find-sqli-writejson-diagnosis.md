# find-sqli-login: почему нуль держится — трасса + write_json, диагноз (2026-09-13)

Стенд: эта машина (RTX 4080), sber-model/sber-eval, qwen2.5-coder:7b-q4, ctx 4096,
образ acp по digest. Добавлен env-gated `AGENT_TRACE_TOOLS` (loop печатает каждый вызов
инструмента; off без переменной, в сабмишн не попадает) — впервые видно, что делает модель.

## Что показала трасса (архив write_json, `--only find-sqli-login`)

| шаги | действие |
|---|---|
| 1–2 | `list_dir` /app |
| 4–8 | `search` — НАХОДИТ `routers/auth.py:17 # VULNERABLE: raw f-string concatenation` |
| 9–10 | `read_range` login-хендлера (видит уязвимый f-string SQL) |
| 12–30 | `write_file` `{"findings": []}` (16 байт, ПУСТОЙ) снова и снова; иногда 0 байт |

Итог: 0, stop=steps, deliverable = пустой отчёт.

## Диагноз (обе прежние гипотезы опровергнуты трассой)

1. **Не потеря на экранировании.** Модель не пишет полную находку, которую бы теряла на
   кавычках — она сразу выдаёт пустой скелет `{"findings": []}`.
2. **Не отсутствие подсказки.** Чекпоинт (доля шагов 0.4 = шаг 12, артефакта ещё нет)
   СРАБАТЫВАЕТ и говорит «перенеси прочитанный код в evidence, пустой findings =
   утверждение о безопасности». Модель всё равно пишет пусто. Это ровно то, что уже
   зафиксировал P2b в `loop.py`: «'write your best now' was answered with
   `{"findings": []}` four times».
3. **Модель НЕ выбирает `write_json`** — привычно берёт `write_file`, хотя инструмент
   предложен в TOOLS и в чекпоинте.

Контроль: та же модель на ПРЯМОЙ запрос (plain completion, без constrained-действия)
выдаёт идеальный полный отчёт с находкой SQLi. Значит потолок — не знание модели, а её
поведение под schema-constrained форматом действия: заполнить длинный отчёт внутри
одного строгого action ей трудно, и она сваливается в минимальный валидный `{"findings": []}`.

## Что сделано (чистые, проверенные части — оставлены)
- `write_json(path, data)` (tools/prompt/loop, тесты): агент сам сериализует JSON,
  модель передаёт значение структурно, без экранирования JSON-в-JSON. Механически верный
  рычаг; НЕ конвертирует, пока модель его не выбирает.
- `AGENT_TRACE_TOOLS` — диагностическая трасса вызовов (env-gated).
- `data`-поле схемы: `additionalProperties: true`, чтобы под strict json_schema объект
  можно было заполнить, а не только `{}`.

## Точные рычаги для следующей итерации (не сделаны — нужен парный замер и ревью)
- Заставить audit-deliverable идти через структурированный путь (write_json как ЕДИНСТВЕННЫЙ
  для .json, либо отдельный обязательный audit-action). Риск шлюза D: не хардкодить
  findings-схему public-задачи.
- Не считать отчёт с пустым `findings` удовлетворяющим артефактом (сейчас пустой отчёт
  гасит чекпоинт на шагах 13+). Требует чтения артефакта — audit-специфично.
- Возможно, только более крупная модель на оценке закроет разрыв; модель оценки задаёт
  организатор.
