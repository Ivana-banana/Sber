# Таксономия четырёх нулей E-BASE — 12.09.2026

Свод по измеренным прогонам (P2 offline-проба, P3 live, P5 live) и разбору
сохранённых логов E-BASE-r1 (`133b81d0…`). Модель `qwen2.5-coder:7b`. Цель — карта
«что реально блокирует каждую задачу», чтобы отделить чинимое от потолка модели.

## 1. `find-sqli-login` — сериализация (чинимо тулингом)

Модель на шаге 9 пишет **верную** находку (SQLi в `auth.py:17`), текстово проходящую
**все три gate** verifier. Провал — невалидный JSON (незакрытая кавычка в `evidence`).
write_file JSON-guard (`f6c10cb`) **измерен**: детектирует, но 7B не чинит
экранирование — коллапс в `{"findings": []}`. reward 0 → 0.
Карточка `P3-writefile-guard-20260912`. **Узкое место — ручная JSON-сериализация**,
не понимание. Кандидат — tool policy (развилка, решает человек).

## 2. `fix-sqli-login` — связанная двухстрочная правка (потолок построения правки)

Verifier-gate в петле **работает**: `verify()` исполняется, finish принимается только
при прохождении; E-BASE остановился по `budget`, не приняв сломанное. Дефект — в том,
что модель не может построить правку. Последовательность `replace_text` (E-BASE):

1. `new: query = await conn.fetchrow('… $1 … $2', req.username, req.password)` —
   **параметры верные**, но результат присвоен в `query`, а строка-потребитель
   `row = await conn.fetchrow(query)` осталась → двойной вызов (`partial`-форма).
2. `new: query = "… $1 … $2"` → `unbound`-форма (плейсхолдеры без значений).
3–5. `old == new`, три холостых no-op.
6. снова `unbound`. Затем `pytest tests/` (падает), finish (отклонён verify), no-op на
   чужом файле, budget исчерпан.

**Модель ни разу не трогает строку-потребитель** `row = await conn.fetchrow(query)`.
Это ровно диагноз P2: правит построение значения, но не зависимое использование.
P2 доказал: prompt-подсказка «менять обе строки вместе» опровергнута 5×; а offline
report-vs-action проба — что ту же полу-починку модель **при опросе диагностирует
верно** (7b и deepseek: `unbound`/`partial` = BROKEN, называют несвязанный параметр).
Значит разрыв — не в понимании изолированного дефекта, а в **координации связанной
правки в петле** (одна строка за раз через `replace_text`, зависимость не удерживается).

## 3. `fix-sqli-search` — тот же класс, что #2

E-BASE deliverable: `query = "SELECT * FROM items WHERE name LIKE $1 ESCAPE '\' ORDER
BY id ASC"` затем `rows = await conn.fetch(query)` — снова параметризовано в `$1`, но
значение `q` не передано в `fetch`; плюс битый `ESCAPE '\'`. **Та же `unbound`
полу-починка.** stop=budget, 0. Два из четырёх нулей — один failure mode.

## 4. `incident-log-forensics` — потолок рассуждения (дорого/недостижимо)

Свежий baseline (P5, `P5-forensic-baseline-20260912`): формат deliverable **верный**
(4 строки, верные ключи), но значения **выдуманы** (`10.0.0.1 / jdoe / 123456789`
против эталона `203.0.113.50 / deploysvc / 2457600`). Шаги 27–30 — осцилляция
`unknown` ↔ придуманное. Мультилог-корреляция (nested JSONL → malicious record →
proxy XFF → exfil bytes) не выполнена. **Модель ответ не выводит.** Тулингом/prompt
дёшево не чинится.
