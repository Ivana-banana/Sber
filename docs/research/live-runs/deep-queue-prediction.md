# Ожидание до прогона: очередь глубоких абляций 07.09.2026

Записано **до** запуска, в 01:1x по местному времени, коммит базы `e0fd6d3`
(runtime байт-в-байт равен архиву E061: `b-deep-base.zip` и `e061-recon-packet.zip`
имеют один SHA-256 `21a43317d6ed…`). Запись существует, чтобы результат нельзя было
объяснить задним числом.

## Что измеряется

Восемь плеч из `docs/superpowers/plans/2026-09-07-deep-ablation-queue.md` §4,
каждое — один фактор от одной замороженной базы B. Блок 1 — шесть публичных задач
организаторов, контроль B в начале и в конце. Блок 2 — восемнадцать локальных фикстур.

| Плечо | Архив | Фактор |
|---|---|---|
| H01a | `e062-h01a-signed-observation` | наблюдение подписано нормализованным действием |
| H01b | `e063-h01b-read-pagination` | границы окна чтения, `eof`, `partial_line` (поверх H01a) |
| H03 | `e064-h03-hypothesis` | два поля плана до действия; снят запрет рассуждать |
| H04 | `e065-h04-task-block` | TASK — цель, файлы и логи — свидетельства |
| H05a | `e066-h05a-audit-procedure` | audit-playbook: процедура вместо списка артефактов |
| H06b | `e067-h06b-checkpoint-probe` | checkpoint просит недостающий факт, а не файл |
| H08 | `e068-h08-content-novelty` | новизна записи по содержимому, а не по длине |
| H09 | `e069-h09-verify-detail` | модель получает саму ошибку проверки |

## Полосы

Контроль. E048 дал 2/6, E049 — 2/6, обе — `hello-file` и `bye-file`. Полоса для
B1 и B2 — **1–3 из 6**; если контроли разойдутся больше чем на одну задачу, стенд
дрейфует и разницу плеч в блоке 1 в этот прогон засчитывать нельзя.
На фикстурах E060 и E061 дали 5/18 обе; полоса B3/B4 — **3–6 из 18**.

Предсказание по плечам, публичный набор (главный критерий — не потерять
`hello-file`/`bye-file`; это два самых дешёвых нуля, какие можно устроить):

- **Ни одно плечо в одиночку не даёт 4/6.** Четыре содержательные публичные задачи
  требуют дойти до нужного исходника, выбрать гипотезу и воплотить её; ни один из
  восьми факторов не отвечает за весь этот путь.
- H08 и H09 — багфиксы контроллера. Ожидаю **0 приобретений и 0 потерь** на публичных:
  H08 доказан на скрипте, но в разобранных отчётах E060 потерянной проходящей версии
  из-за него не найдено, а на публичных задачах красная проверка встречается редко.
  Их место — блок 2.
- H06b — единственное плечо с реальным риском регрессии: убрав «запиши хоть что-нибудь»,
  можно потерять `hello-file`/`bye-file`. Если они выживают — фактор безопасен,
  и это главное, что нужно узнать про него.
- H03 дороже остальных по токенам: ожидаю **рост tokens/call на 5–20%**. Если solved
  не вырос, фактор не принимается, каким бы разумным ни выглядел текст гипотез.
- H05a дешевле базы: audit-playbook стал вчетверо короче, ожидаю **снижение
  tokens/call на 3–8%** на задачах, попавших в code-audit.

Опровержение по всей очереди: если каждое плечо даёт 2/6 и те же две задачи, ночь
измерила, что ни один из восьми факторов не двигает публичную решаемость по одному,
и следующий шаг — диагностика D0–D3 из §3 плана, а не девятое плечо.

## Чего этот прогон не доказывает

Один прогон на плечо. Разброс solved на неизменном коде здесь уже наблюдался равным
трём задачам из восемнадцати (E032/E033), поэтому **разница в одну задачу — не
результат**, а повод для повтора. Локальные фикстуры не переносятся на закрытый набор.
`ever_passed_offline` из §5 плана здесь не вычисляется: harness не сохраняет
промежуточные версии кандидата.
