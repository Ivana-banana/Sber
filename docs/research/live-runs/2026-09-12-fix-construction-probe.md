# fix-sqli: построение правки vs локализация в петле — 12.09.2026

## Вопрос

Измеренный fix-sqli-login даёт полу-починку: query параметризуется (`$1/$2`), а вызов
`fetchrow(query)` ниже остаётся без переданных значений — модель **никогда не трогает
строку-потребитель**. Два чтения: потолок способностей на связанной правке, либо
артефакт петли (правит по одной anchored-строке через `replace_text`, не координирует
две). P2 показал, что дефект модель **диагностирует** верно; здесь проверяем, может ли
она **построить** правку.

## Метод

`scripts/eval/probe_fix_construction.py`. Модели дают **целиком** уязвимую функцию
`login` (из `local_task/fix-sqli-login/.../auth.py`) и просят вернуть исправленную
функцию целиком — без локализации и якорей. temp 0, три повтора, через прокси стенда
(переиспользуется загруженная модель, digest 7b `dae161e27b0e`). Грейдер: `$1/$2`,
нет f-string интерполяции значения, и `req.username`/`req.password` переданы
**аргументами** в `fetchrow` (потребитель изменён вместе с запросом).

## Результат

**3/3 correct.** Модель выдаёт корректную связанную правку:

```python
query = "SELECT id FROM users WHERE username = $1 AND password = $2"
row = await conn.fetchrow(query, req.username, req.password)
```

Устойчиво по трём повторам (варьируется лишь форма строкового литерала).

## Вывод

- fix-sqli — **не потолок способностей**. Дав функцию целиком, 7B строит правильную
  связанную правку надёжно.
- Блокер — в **петле**: модель редактирует по одной anchored-строке через
  `replace_text` (а playbook ещё и требует «minimal diff / small patch»), застревает на
  строке построения и не переписывает потребителя. Дав ей переписать функцию целиком,
  она справляется.
- **Рычаг (доказан пробой):** направить code-fix на **переписывание всей функции**
  через `write_file`, а не построчные anchored-правки. Это другой механизм, чем
  опровергнутая 5× подсказка «менять обе строки в одном replace_text».
- Ожидаемо переносится на fix-sqli-search (тот же класс полу-починки).

## Ограничения

- Проба даёт модели функцию на блюде; в петле добавляется локализация функции и выбор
  «переписать целиком». Проба доказывает только звено построения. Следующий фактор
  (playbook-steer к whole-function rewrite) надо измерить живым прогоном.
- temp 0, n=3 через один стенд — детерминизм этого стенда, не переносимость.
