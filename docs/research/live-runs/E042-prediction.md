## Фактор

блоков. Перевод, а не переписывание — порядок шагов, формулировки и «что сохранить»
сохранены, чтобы меняющейся величиной был только язык. Измерение и метод —

у control есть измеренный разброс, и полосы ниже построены по нему, а не по одному
прогону:

Отсюда правило для этой карточки: **суммарные токены и число вызовов критериями быть
не могут** — они гуляют на 14–17% при неизменном коде, потому что зависят от того,
сколько шагов задачи успели прожить. Судить надо величины на вызов.

1. **Токенов на вызов: 1090–1180.** Прямая проверка механизма: 1268 (среднее control)
   минус 155 сэкономленных, полоса ±5%.
2. Solved — gate, **2–5 из 18**. Обе точки control дали 3.
3. Задач с deliverable **11–15**.
4. Нормированный первый вызов **3.6–4.4**. Фактор укорачивает префикс, но префикс

5. Нормированная медиана шагов 9–12 **1.1–1.8** — фактор её не трогает.
6. Запросов на шаг **0.95–1.05**.

## Что считать опровержением

- **solved ≤ 1** — перевод стоил задач; язык влияет на качество, и запись «фактор 9 не
  установлен» получает знак. Откат немедленный;
- токенов на вызов **не ниже 1200** — экономия не материализовалась, значит выросло
  что-то другое, и надо смотреть что;
- deliverable меньше 11 — расходится с двумя прогонами control подряд.

## Чего этот прогон не докажет

Перевод меняет две величины сразу: цену резидента в токенах и число языков в контексте
(публичные задания английские, контракт был русским). Одним прогоном их не разделить.
Если solved вырастет, приписывать это языку нельзя без третьего прогона, где
переведён только один из двух блоков.

И, как всегда: один прогон восемнадцати публичных задач не говорит о закрытом наборе.
Абсолютные значения токенов надо будет сверить с `prompt_tokens` самого endpoint —
локальный токенизатор это заменитель, расхождение на русском скелете было 21 токен.
