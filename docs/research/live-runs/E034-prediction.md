# E034 — ожидание, записанное до запуска

Дата записи: 04.09.2026, до сборки архива.
Ветка `eval/e034-prompt-order` поверх состояния E032/E033.
Control — **E033** (`2/18`), тот же код плюс ровно один фактор.

## Фактор

Порядок блоков системного prompt: общее между задачами вперёд, уникальное назад.
Было `skeleton → instruction → brief → playbook`, стало
`skeleton → playbook → brief → instruction`. Ни одно слово prompt не изменено,
число токенов то же.

## Почему ожидается эффект — замеры на самом стенде

| замер | результат |
|---|---|
| prefill | ~29 мс на некэшированный токен (34 tok/s) |
| decode | 6.2 токена/с |
| повтор того же prompt | 0.7 с независимо от длины — кэш префикса идеален |
| общий префикс + новый хвост | 11.3 с против 34.5 с холодных |
| контроль без общего префикса | 30.2 с — экономию даёт именно префикс |
| текущий порядок, соседние задачи | 22.1 с на первый вызов |
| предложенный порядок, соседние задачи | **14.1 с**, тот же 1038-токенный prompt |

Устойчиво в обе стороны прогона (14.0–14.1 против 21.6–22.9).

Из логов E033: первый вызов каждой задачи стоит 44.8 с в среднем и составляет
**33% всего времени `plan`**; 75% времени задачи уходит **до** первой записи
deliverable, медиана первой записи — 126 с из 180.

## Предсказание

Основные метрики — **непрерывные**, они измеряют механизм и почти не шумят:

1. медиана первого `plan`-вызова: 39.2 с → **ожидается 30–33 с**;
2. суммарное время первых вызовов: 806 с → **ожидается 650–700 с**;
3. медиана времени до первой записи deliverable: 126 с → **ожидается 118–122 с**;
4. общее число `plan`-вызовов: 156 → **ожидается рост на 5–10%**;
5. токены: ожидается **без изменений** (±2%), число токенов prompt то же.

Solved — только gate, не доказательство: **ожидается 2–4 из 18**.
После E033 известно, что разброс solved на неизменном коде равен 3 задачам,
поэтому по одному прогону solved ничего не доказывает ни в плюс, ни в минус.

## Что считать опровержением

- медиана первого вызова не упала ниже 36 с — механизм на реальном prompt не
  воспроизводится, и стендовый замер измерял что-то другое;
- solved = 0 или 1 — фактор навредил, и это надо разобрать по trace, а не списать
  на разброс, несмотря на известный шум;
- рост токенов больше 2% — значит изменился не только порядок.
