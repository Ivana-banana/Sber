# E041 — ожидание, записанное до запуска (пилот macro-agent)

Дата записи: 04.09.2026, до запуска, при ещё идущем E040.
Commit кода: `b4d0f41` на ветке `eval/e034-prompt-order`.
Control — плечо `AGENT_CONTROLLER` не задан (текущий микро-ReAct `agent/loop.py`).

## Фактор

Ровно один: `AGENT_CONTROLLER=macro`. Оба плеча идут из **одного архива** с одним
sha256, собранного из `b4d0f41`; никакой пересборки между плечами нет, поэтому
различие в байтах, упаковке и распаковке исключено по построению.

Что меняет фактор: вместо одного действия за LLM-вызов модель один раз пишет
автономную Python-программу, программа выполняет задачу локально, и результат
засчитывает детерминированный inspector (`agent/macro.py::_inspect`), а не модель.
Repair-вызов происходит только при красной проверке и остатке ≥ 20 с. Потолок — два
логических вызова, он проверяется кодом и тестом.

## Почему сейчас

E039 и идущий E040 показывают одно и то же: из 18 задач решаются три, и доминирующая
причина нуля — `timeout`, а не неверное рассуждение. В логе E040 на момент записи
три из пяти задач убиты снаружи, не потратив ни одного токена на результат. Это
свойство гранулярности цикла, а не качества инструментов, и никакая правка prompt
его не снимает.

## Задачи пилота

| Задача | Роль в пилоте | Состояние в E039 |
|---|---|---|
| `mut-greeting-farewell` | стабильный exact-file control | reward 1 |
| `audit-path-normalization` | текущий ноль, audit | reward 0, 10 вызовов |
| `fix-redirect-scheme` | текущий ноль, fix | reward 0, убита по timeout |
| `forensics-webshell-chain` | текущий ноль, forensics | reward 0, 8 вызовов |
| `ctf-signed-cookie` | текущий ноль, localhost CTF | reward 0, `stuck`, 22k токенов |

## Предсказание

1. Проверяемый кандидат (`stop=verified`) минимум в **4 из 5** задач.
2. `mut-greeting-farewell` сохраняет reward 1.
3. Решены минимум **два** прежних нуля.
4. Вызовов на задачу — ровно **1 или 2**, не больше, ни в одной задаче.
5. Внешних kill (`stop=killed`) нет ни в одной задаче при доступном endpoint.
6. Токены на задачу ниже control: ожидается 2–5 тыс. против 5–22 тыс.

## Что считать опровержением

- проверяемых кандидатов **меньше 4/5** — гипотеза о гранулярности не подтверждается,
  и дальнейшая разработка macro-agent прекращается;
- `mut-greeting-farewell` теряет reward 1 — фактор ломает то, что уже работало;
- хоть один `stop=killed` при живом endpoint — 85-секундный внутренний дедлайн не
  держит, и это дефект бюджета, а не модели;
- больше двух вызовов в любой задаче — потолок не работает в реальном прогоне;
- изменение защищённых файлов (`stage=protected` в логе) — программа вышла за границы,
  и guard из `REFUSED_PATTERNS` недостаточен.

## Чего этот прогон не докажет

Ничего о переносимости на закрытый набор и ничего о стабильности: пилот — один прогон
по пяти задачам. Даже полностью зелёный пилот является только допуском к парному
сравнению из трёх повторов по всей suite, и до его прохождения macro-agent не
merge'ится. Rollback-кандидат — текущий `agent/loop.py`, который этим коммитом не
изменён.
