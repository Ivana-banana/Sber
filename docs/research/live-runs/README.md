# live-runs — сырые таблицы прогонов против настоящей модели

Одна строка на задачу, ровно то, что напечатал `scripts/eval/run_suite.py`. Лежат в
репозитории, потому что карточки в `docs/experiments.md` ссылаются на эти числа, а
проверить утверждение по пересказу нельзя. Файлы маленькие (~1 КБ), тяжёлые логи и
трассы сюда не едут — они воспроизводятся командой из карточки.

| Файл | Прогон | Изменённый фактор | Решено |
|---|---|---|---:|
| `E011-results.tsv` | baseline | — | 0/18 |
| `E012-results.tsv` | политика путей | workspace по тексту задачи + запись по названным путям | 3/18 |
| `E013-results.tsv` | застревание → производство | **откачено**: 0 прироста, +23% токенов | 3/18 |
| `E014-partial-results.tsv` | конверт ответа | **прогон оборван** на 5-й задаче из 18 | — |

Колонки: `reward` — вердикт верификатора самой задачи (`/logs/verifier/reward.txt`),
единственное, что считается результатом; `tokens` — то, что агент сообщил о себе сам
(`?`, если его убили раньше); `ep_tokens`/`ep_calls` — независимый счётчик на endpoint;
`claim` — что агент сам думал о своём результате. Расхождение `claim=True` при
`reward=0` — это класс `verification`, самый дорогой: прогон остановился, считая себя
готовым.

`E014-partial-results.tsv` — не результат, а сохранённая улика. Прогон убит вместе с
контейнерами модели и прокси после 5 из 18 задач, ни одна из трёх решаемых E012 задач в
этот префикс не попала, поэтому решаемость по нему не считается вообще. Что в нём видно:
при `temperature 0` три из пяти строк совпали с E012 до токена, а `ctf-header-override`
перестал быть ложной победой (`claim=True, reward=0`) и честно упёрся в `stuck`. Полный
прогон фактора нужно повторить.

Модель прогонов — `qwen2.5-coder:7b` на CPU. Это **не** модель оценки, и ни одно число
отсюда не переносится на закрытый набор; ограничения перечислены в карточках.
