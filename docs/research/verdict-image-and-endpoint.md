Дата: 25.08.2026. Исходники — `target-image-manifest.md` (запрос M1),
`endpoint-behaviour.md` + `endpoint-behaviour-code-review.md` +

## 1. Проверка достоверности

Перепроверено независимо от Manus, с нашей машины, 25.08.2026.

| Что проверяли | Как | Результат |
|---|---|---|
| Теги, digest, дата, размер образа | Docker Hub Tags API | Совпало до байта: два тега `latest` и `harbor-0.16.1`, оба `sha256:1324d7bb…c8a3`, `2026-07-02`, 633 598 038 Б |
| Версия Harbor в образе | wheel `harbor==0.16.1` с PyPI, sha256 совпал с индексом PyPI | Пакет существует, версия доступна |
| Что отчёт цитирует реальный образ | `harbor/agents/installed/acp.py` из wheel против `acp.py`, извлечённого Manus из слоёв | **Побайтово идентичны** |

Третья строка — сильная проверка: файл, вытащенный из слоёв образа, совпал с
файлом из независимого источника. Отчёт M1 принимается как достоверный.

Побочный результат важнее самой проверки: **исходники Harbor 0.16.1 доступны нам
локально с PyPI**, без Docker и без Manus. Блокер «нельзя поднять контейнер» не
мешает читать контракт запуска — он мешает только исполнить его.

## 2. Что принимаем как факты среды

Из `target-image-manifest.md`, платформа `linux/amd64`:

- Debian 12 bookworm, CPython **3.12.13**, `WORKDIR /app`, `USER` не задан (root),
  `CMD ["harbor","--help"]`, `ENTRYPOINT` отсутствует.
- `PATH` начинается с `/app/.venv/bin` — значит `python3` в задаче это venv-python.
- **В venv нет `pip`** ни как модуля, ни как исполняемого файла. Установка пакетов
  во время прогона невозможна физически, а не только по правилам.
- В venv есть `harbor 0.16.1`, `openai 2.44.0`, `anthropic`, `litellm`, `langchain*`,
  `langgraph`, `llama-index`, `crewai`, `pydantic-ai`, `mcp`, `httpx`, `requests`,
  `uv 0.11.26`.
- Есть: `git`, `curl`, `wget`, `rg`, `grep`, `jq`, `zip`/`unzip`, `tar`, `patch`,
  `gcc`, `make`, `objdump`, `readelf`, `strings`, `file`, `nc`, `tcpdump`, `openssl`.
- **Нет:** `sqlite3`, `gdb`, `nmap`, `tshark`, `node`, `java`, `php`, `docker`,
  `strace`, `ltrace`, `xxd`, `hexdump`, `binwalk`, `exiftool`, `yara`, `socat`,
  `volatility`, `radare2`, `yq`.
- Пользовательского примера агента или `run.sh` в `/app` нет.

Отсутствие `sqlite3`, `xxd`/`hexdump` и `gdb` — прямое ограничение для playbook'ов
forensics и CTF: разбор БД и бинарей делаем python-stdlib (`sqlite3` как **модуль**
python в образе есть, CLI — нет), дамп байтов — python, а не `xxd`.

## 3. Поправка, которой в отчёте нет: где именно исполняется агент

Отчёт инвентаризовал `secureintelligent/acp` и на этом остановился. Агент,
однако, исполняется не в нём напрямую. Проверено по исходникам Harbor 0.16.1
и по upstream-комплекту на закреплённом SHA `71f9081`:

| Факт | Источник |
|---|---|
| Каждая public-задача собирает свой образ `FROM secureintelligent/acp:latest` | `local_task/*/environment/Dockerfile` |
| Часть задач доустанавливает пакеты на этапе **сборки** (`apt-get install postgresql`, `uv pip install .`) | `local_task/find-sqli-login/environment/Dockerfile` |
| Организаторский агент грузит **весь каталог рядом с `agent.py`** в `/opt/harbor/local-agent` | `agent/agent.py`, `install()` → `environment.upload_dir` |
| Он же делает `chmod +x /opt/harbor/local-agent/run.sh` | `agent/agent.py`, `install()` |
| Запуск: `cd /opt/harbor/local-agent && ./run.sh "<instruction>" 2>&1 \| tee /logs/agent/local-agent.txt` | `agent/agent.py`, `run()`; `EnvironmentPaths.agent_dir = /logs/agent` |
| Harbor оборачивает любую команду в `set -o pipefail; …`, ненулевой код → `NonZeroAgentExitCodeError` | `harbor/agents/installed/base.py`, `_exec` |
| Переменные приходят как env процесса: `LOCAL_AGENT_MODEL` (= model name), `OPENAI_BASE_URL`, `OPENAI_API_KEY` | `agent/agent.py`, `run()` |
| Лимит времени агенту **не передаётся** — ни аргументом, ни переменной | `agent/agent.py`; таймаут применяет `SingleStepTrial._run_agent` снаружи |
| `/tests` копируется в среду **после** работы агента; `/solution` — только для OracleAgent | `harbor/models/trial/paths.py` |

Следствия, каждое из которых меняет наш код:

1. **`run.sh` должен лежать в корне того, что распаковано рядом с `agent.py`.**
   Гипотеза от 24.08 подтверждается механикой: `upload_dir` берёт каталог целиком,
   запуск идёт как `./run.sh` из этого каталога. Вложенный верхний каталог
   (`sample_submission/run.sh`) при таком запуске не найдётся.
2. **Рабочий каталог агента — свой собственный (`/opt/harbor/local-agent`), а не
   каталог задачи.** Материал задачи лежит отдельно (в public-задачах — `/app`).
   Наш preflight обязан искать workspace, а не считать `cwd` рабочей директорией.
3. **Ненулевой exit code — наблюдаемая ошибка**, `pipefail` включён Harbor'ом.
   `run.sh` обязан выходить с 0 даже когда агент внутри сдался.
4. **Агент не знает своего лимита времени.** Значение приходится предполагать.
5. **Тестов во время работы агента в среде нет.** Подменить проверку невозможно
   технически; правило CLAUDE.md совпало с механикой.

## 4. Лимиты: первые измеренные числа вместо догадок

Прочитано из шести public `task.toml` на SHA `71f9081`:

| Задача | agent `timeout_sec` | verifier | cpus | memory_mb | allow_internet |
|---|---:|---:|---:|---:|---|
| bye-file | 120 | 120 | 1 | 2048 | true |
| hello-file | 120 | 120 | 1 | 2048 | true |
| find-sqli-login | 600 | 120 | 2 | 4096 | true |
| fix-sqli-login | 600 | 240 | 2 | 4096 | true |
| fix-sqli-search | 600 | 240 | 2 | 4096 | true |
| incident-log-forensics | 600 | 120 | 1 | 2048 | true |

`DEFAULT_TASK_TIMEOUT_S = 600.0` в `agent/limits.py` совпадает с потолком сложных
public-задач, но для тривиальных лимит в **пять раз меньше**. Агент лимита не
получает, значит планировать нужно от худшего known значения, а не от лучшего.
Это открытая задача, не сделанная правка: числа в `limits.py` пока не тронуты.

Отдельно: 1–2 CPU и 2–4 ГБ памяти. Тяжёлые локальные вычисления и параллельные
процессы в бюджете не помещаются.

## 5. Что принимаем из M3 по клиенту endpoint

Отчёт `endpoint-behaviour-code-review.md` называет девять расхождений
`agent/llm.py` с документированным поведением vLLM, SGLang, llama.cpp, Ollama,
TGI и LM Studio. Разбор по нашему ранжированию:

| # | Расхождение | Наша оценка | Приоритет |
|---:|---|---|---|
| 1 | Пустой `OPENAI_API_KEY` считается фатальной ошибкой конфигурации | **Принято, это путь к нулю.** Локальные серверы keyless по умолчанию; при пустом ключе агент не сделает ни одного запроса и потеряет все 15 задач | **P0** |
| 2 | Downgrade протокола на любой 4xx | **Принято.** 401/404/429 не означают несовместимость формы запроса; сейчас rate limit превращается в необратимое понижение | **P0** |
| 3 | Retry того же body на 5xx | **Принято.** llama.cpp документированно отдаёт 500 на неполные tool arguments; при `temperature=0` повтор бессмыслен — это наш же принцип, нарушенный в коде | **P1** |
| 4 | Парсер принимает только `tool_calls: list` и `arguments: str` | **Принято.** TGI отдаёт объект и `function.parameters`; успешный ответ классифицируется как мусор | **P1** |
| 5 | `tool_choice` всегда OpenAI named-object | **Принято.** Ollama не поддерживает `tool_choice`, TGI ждёт строку | **P1** |
| 6 | Форма `response_format.json_schema` | **Принято частично.** llama.cpp документирует top-level `schema`. Лечится попыткой обеих форм на этом уровне | **P2** |
| 7 | Берётся только `calls[0]` | **Принято как наблюдаемость.** Протокол у нас один `emit_action`, но лишние calls — признак дефекта, их надо видеть в логе, а не молча терять | **P2** |
| 8 | Нет валидации результата против schema | **Принято.** Валидный JSON с чужими ключами сейчас считается успехом | **P2** |
| 9 | Tool call, оставшийся в `content` | **Принято как диагностика**, не как обязательный salvage | **P3** |

**Расходимся с рекомендацией отчёта в одном.** Manus рекомендует стартовый уровень
`TEXT` как самый переносимый. Для нашего ранжирования это дорого: текстовый уровень
даёт худшую структурность, а значит больше повторов и токенов на всех 15 задачах.
Решение от 25.08 остаётся в силе — стартовый уровень выбирается **по результату
`scripts/probe_endpoint.py` на реальном endpoint**, а не по общей рекомендации.
`TEXT` принимается как значение по умолчанию только на случай, если probe провести
не удалось.

Второе уточнение: пункты 1 и 2 — не «улучшение совместимости», а багфиксы. Каждый
начинается с воспроизводящего теста на фейковом endpoint, как требует `CLAUDE.md`.

## 7. Что осталось непроверенным

- Инвентаризация относится к `linux/amd64`. Слои `arm64` не скачивались.
- Образ проверен через распаковку слоёв и `chroot`, а не запуском контейнера.
  Поведение systemd-зависимых вещей, сети и лимитов ресурсов не проверялось.
- Закрытые задачи могут собирать среду из другого `Dockerfile`. Совпадение
  «среда задачи наследует `acp`» доказано только для шести public-задач.
- Тег `latest` может быть перевыпущен. Мы фиксируем digest, а не тег.
- Поведение endpoint'а оценки неизвестно: какой сервер инференса и какая модель
  за `OPENAI_BASE_URL`, не сказано нигде. Все выводы M3 — про классы серверов.
- Утверждение «упавший агент всё равно проходит verifier» верно для механики
  Harbor 0.16.1 (`SingleStepTrial._run_agent` глотает таймаут и ненулевой код,
  после чего безусловно вызывается `_run_verifier`). Регламент организаторов
  говорит, что crash и timeout дают `0`. При расхождении приоритет у регламента:
  считаем, что падать нельзя, а механику Harbor держим как страховку, а не как
  разрешение падать.
- Скрипты в `target-image-audit/` — чужой код из отчёта. Они сохранены для
  воспроизводимости и **не запускались нами**; перед запуском прочитать.
