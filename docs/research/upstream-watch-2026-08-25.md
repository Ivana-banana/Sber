## 3. Проверка репозитория и контракта сдачи

Состояние дерева на текущем `HEAD` совпадает с базовым состоянием. В репозитории присутствуют `agent/agent.py`, `agent/run.sh`, `agent/local_agent.py`, `sample_submission.zip`, шесть каталогов с `task.toml` в `local_task/` и каталог `local_task/insecure-api-app` без собственного `task.toml`. Оцениваемые публичные packages остаются теми же: `bye-file`, `hello-file`, `find-sqli-login`, `fix-sqli-login`, `fix-sqli-search`, `incident-log-forensics`. `insecure-api-app` остаётся общим fixture/generator для SQLi-задач, а не седьмой задачей.

README на текущем HEAD по-прежнему говорит, что `local_task/` предназначен только для локальной разработки и в официальной оценке используется закрытый набор. Он требует ZIP-архив с как минимум `run.sh`, указывает вызов `./run.sh "<task instruction>"`, описывает заменяемый организаторами `agent/agent.py`, офлайн microVM, невозможность установки зависимостей во время прогона, переменные `LOCAL_AGENT_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`, а также среду `secureintelligent/acp:latest` с Python 3.12 и Harbor 0.16.1 [1]. Это соответствует приложенному описанию.

Существенная особенность, уже отражённая в приложении, сохраняется: README описывает обязательный `run.sh` на требуемом уровне, тогда как `sample_submission.zip` имеет верхний каталог `sample_submission/`, внутри которого находится `run.sh`. Поэтому layout архива остаётся неустранённым вопросом совместимости: перед финальной отправкой следует прогнать Harbor smoke-тест для фактического submission и получить подтверждение организаторов, если от этого зависит упаковщик.

Проверка PR-истории показывает, что последняя содержательная публикация была исправлением reference solutions для `fix-sqli-login` и `fix-sqli-search`: решения стали ждать локальный сервис перед regression tests; это относится к публичным reference solutions и не меняет контракт финальной сдачи агента [7]. Ранее опубликованные исправления fixtures/entrypoint и stream events также находятся до базового SHA [5] [6].

## 5. Проверка образа `secureintelligent/acp`

Docker Hub API возвращает два тега: `latest` с `last_updated = 2026-07-02T14:57:25.825344Z` и `harbor-0.16.1` с `last_updated = 2026-07-02T15:00:01.357552Z`. Для обоих указан общий manifest-list digest `sha256:1324d7bb140422a9929f5bc538f55ec0480d2731742effee02bf67604130c8a3`. Дайджесты платформенных манифестов: Linux/amd64 — `sha256:5a93249d3dfd44dbf2e83806f89ce2662a3e575c8ad0fb5c54feb03ec5626132`; Linux/arm64 — `sha256:60f32b3e722fcfdd6dc3a5f42f8e2a1860cc5c390583616cbfaa45785bf530a3` [2] [12].

Поэтому новых тегов не обнаружено, а `latest` и `harbor-0.16.1` на момент проверки имеют одинаковый digest. Поскольку доступная история Docker Hub не даёт полного журнала прежних переназначений тегов, утверждение ограничено текущим публичным состоянием: **текущий digest совпадает с зафиксированным в приложении**, но абсолютную неизменность за весь период без ранее сохраненных манифестов доказать нельзя.

Это уточнение степени доказанности, а не обнаруженное изменение [2] [12].

5. **Непроверяемые в публичном комплекте вопросы сохраняются:** конкретные лимиты закрытых задач, модель/инференс-сервер за `OPENAI_BASE_URL`, Dockerfile закрытой среды и строгий формат финального ответа не опубликованы в проверенных источниках.
