# Почему `mut-audit-query-gate` теряется под английским резидентом

Разбор сделан 04.09.2026 по четырём прогонам: E039 и E040 (русский резидент, задача
решена 2/2) против E042 и E046 (английский, 0/2). Источник — `logs/*.trace` в каталогах
прогонов: трасса хранит аргументы каждого вызова, включая полное `content` у
`write_file`. Ничего не переигрывалось, все цитаты ниже — из сохранённых трасс.

## Что проверяет задача

`local_task_extra/tasks/mut-audit-query-gate/tests/check.py` требует от
`/workspace/review/findings.json` ровно одно наблюдение с четырьмя ключами, точными
`kind` и `component` и одним условием на текст:

```python
if 'login_name' not in f['proof'] or not f['remedy'].strip(): raise SystemExit(1)
```

`instruction.md` просит это прямо: «include the actual `login_name` data flow in
`proof`». То есть проверка требует буквального идентификатора, названного в задании.

## Что писал агент

Все четыре прогона убиты внешним kill на 180 с, все четыре успели написать
`findings.json`, и во всех четырёх `kind`, `component` и `remedy` верны. Различается
**только** `proof` в последней записи — а побеждает именно последняя.

| прогон | записей в файл | `login_name` в последней | reward |
|---|---:|---|---:|
| E039 (рус.) | 2 | **да**, «The `login_name` parameter is directly included…» | 1 |
| E040 (рус.) | 2 | **да**, та же формулировка | 1 |
| E042 (англ.) | 3 | **нет** | 0 |
| E046 (англ.) | 2 | **нет** | 0 |

Два разных механизма, а не один:

1. **E042 — агент уничтожил собственный проходящий артефакт.** Вторая из трёх записей
   содержала «The `login_name` parameter is used in the query string without any form of
   escaping», то есть **прошла бы проверку**. Третья заменила её общей фразой «user
   input without proper sanitization», и `login_name` исчез. Задача была решена и
   расстала быть решённой без единого сигнала об ошибке.
2. **E046 — конкретика не появилась вовсе.** Обе записи говорят «user input» и
   перефразируют друг друга; вторая ничего не добавляет.

Русские прогоны шли тем же путём: первая запись — та же общая фраза без `login_name`,
вторая — конкретная, с идентификатором. Разница между языками в этих четырёх точках не
в качестве первой попытки, а в том, чем оказывается **переписывание**: улучшением или
перефразировкой.

## Дефект, который это вскрывает, языка не касается

Перезапись артефакта ничем не защищена. Более того, петля к ней **подталкивает**:
`agent/loop.py:91` при исчерпании раннего дедлайна вставляет наблюдение «Запиши лучший
вариант через `write_file` сейчас, улучшишь потом», а `agent/loop.py:513-524`
безусловно отдаёт запись в `tools.write_file`, который просто заменяет файл. Ни одного
условия на то, что новая версия не хуже предыдущей, в пути нет.

Насколько это частая ситуация — посчитано по всем четырём прогонам, 72 задачам:

- путей, записанных больше одного раза: **34**;
- из них таких, где очередная запись **теряет** буквальный литерал из `instruction.md`
  (любой токен в обратных кавычках), который был в предыдущей версии: **2**
  (`mut-audit-query-gate` в E042, `audit-path-normalization` в E046).

То есть переписывание — обычное дело и обычно безвредно, но у него есть редкий
разрушительный исход, и один из двух случаев стоил ровно той задачи, из-за которой
английский резидент не принят.

## Кандидат в лечение (не реализован)

Храповик по литералам задания: перезапись того же пути не должна терять токен в
обратных кавычках из `instruction.md`, который присутствовал в предыдущей версии. При
потере — оставить прежнюю версию и вернуть модели наблюдение с перечнем того, что
пропало. Правило выводится из текста задания, а не из фикстур, так что хардкодом
публичных кейсов не является.

Чего это лечение **не** делает: не помогает E046, где `login_name` не появлялся никогда,
и не спасает случай, когда проверка требует не литерала из задания, а смысла. Цена —
один лишний путь в обработке записи; выигрыш по этим четырём прогонам — одна задача из
двух потерянных. Мерить надо прогоном с предзарегистрированным ожиданием, а не
рассуждением.
