# Замены отсутствующих утилит: протокол проверки внутри целевого образа

Дата: 26.08.2026. Это наш собственный ответ на пункт 3 запроса M16 после того, как
отчёт Manus был отклонён (`verdict-image-cookbook.md`). Отличие одно и существенное:
каждая команда ниже **выполнена внутри целевого образа**, а не выведена из его
описания.

Среда прогона:

```
docker run --rm --network none --entrypoint sh \
  sha256:1324d7bb140422a9929f5bc538f55ec0480d2731742effee02bf67604130c8a3 -c '<команда>'
```

Тот же digest, что зафиксирован в `target-image-manifest.json` и прогоне E003.
Сети нет, PID 1 — `sh`, пользователь root, Python 3.12.13 из `/app/.venv`.

## 1. Инвентарь, снятый заново

`command -v` по 57 именам. Отличия от списка, который был вписан в промпт M16:

| Утилита | Промпт M16 | Фактически в образе |
|---|---|---|
| `perl` | не упомянут | **есть**, `/usr/bin/perl` |
| `nm`, `ld` | не упомянуты | **есть** |
| `od`, `base64`, `ss`, `ip`, `ping`, `ps`, `timeout`, `less`, `stat`, `sha256sum`, `md5sum` | не упомянуты | **есть** |
| `xxd` | не упомянут | **отсутствует** |
| `tcpdump` | назван присутствующим | есть, и это важнее, чем показалось Manus — см. §2.3 |
| `sqlite3`, `gdb`, `nmap`, `tshark`, `node`, `java`, `php` | названы отсутствующими | подтверждено, отсутствуют |

Python-модули (тот же прогон, `importlib.import_module`): доступны `sqlite3`,
`struct`, `socket`, `hashlib`, `base64`, `gzip`, `zipfile`, `tarfile`, `csv`, `json`,
`re`, `ssl`, `http.server`, `email`, `binascii`, `difflib`, `dis`, `ast`, `tokenize`,
`urllib.request`, `secrets`, `hmac`, `uuid`, `shlex`, `pty`, а также сторонние
`requests`, `pydantic`, `openai`, `yaml`, `cryptography`, `numpy`, `tiktoken`.
Не импортируется `pytest`.

**`tiktoken` 0.13.0 установлен, но офлайн неработоспособен.** Проверено отдельно:
`tiktoken.get_encoding("cl100k_base")` тянет BPE-файл с
`openaipublic.blob.core.windows.net` и под `--network none` падает с
`ConnectionError`. Наш вывод о том, что счётчики токенов должны быть записанными
константами, остаётся верным, но его обоснование в `agent/playbooks.py` и
`agent/prompt.py` было сформулировано неверно («tiktoken отсутствует») и исправлено
в этом же коммите.

## 2. Проверенные замены

Ровно пять. В `agent/preflight.py` попали только они: для утилиты без проверенной
замены брифинг сообщает отсутствие и молчит, потому что неверный второй план дороже
отсутствующего.

### 2.1. `sqlite3` CLI → stdlib `sqlite3` в режиме read-only

```
python3 -c "import sqlite3; con = sqlite3.connect('file:PATH?mode=ro', uri=True); ..."
```

Прогон на БД с таблицей `users`:

```
tables: ['users']
row: (1, 'deploy', 'sk_live_x')
write blocked: attempt to write a readonly database
```

Режим `mode=ro` не декоративный: `INSERT` действительно отвергается движком. Это
важно для forensics-задач, где изменение улики — сама по себе ошибка.

Теряется интерактивная оболочка, `.dump`, `.recover` и CSV-режим CLI. Для инвентаря
таблиц и выборки этого достаточно.

### 2.2. `xxd` → `od`

```
od -A x -t x1z -v FILE
```

Прогон:

```
000000 d4 c3 b2 a1 02 00 04 00 00 00 00 00 00 00 00 00  >................<
000010 ff ff 00 00 01 00 00 00 00 1e 85 66 40 e2 01 00  >...........f@...<
```

Смещения шестнадцатеричные, 16 байт в строке, ASCII-панель справа — то же, за чем
идут к `xxd`. Обратного преобразования (`xxd -r`) нет; для него `base64 -d` или
Python.

### 2.3. `tshark` → `tcpdump -nn -r`

**Это главная находка раздела.** Manus написал ради этой замены свой разборщик pcap
на `struct`, который умеет отдавать только временную метку, длины и SHA-256 кадра.
`tcpdump` присутствует в образе — он был в списке самого промпта M16 — и читает файл
без сети и без привилегий:

```
$ tcpdump -nn -r /probe/sample.pcap
reading from file /probe/sample.pcap, link-type EN10MB (Ethernet), snapshot length 65535
09:46:40.123456 IP 10.0.0.1.443 > 10.0.0.2.80: Flags [S], seq 1, win 4096, length 0
```

Полная диссекция: IP-адреса, порты, флаги TCP, seq, окно. Именно эти поля нужны
форензик-задаче, и именно их разборщик Manus не даёт. Ограничение объёма — штатным
`-c N`, а не внешним счётчиком.

Что теряется против `tshark`: pcapng (`tcpdump` читает classic pcap), display
filters уровня Wireshark, реассемблирование TCP-потоков и экспорт объектов. Для
задач такого набора это приемлемо; при необходимости фильтр задаётся выражением
BPF прямо в `tcpdump`.

### 2.4. `gdb` → `objdump` / `readelf` / `nm` / `strings`

Прогон на бинарнике, собранным тем же `gcc 12.2.0` из образа:

```
file:    ELF 64-bit LSB pie executable, x86-64, dynamically linked, not stripped
readelf: Class ELF64 / Type DYN (PIE) / Machine x86-64
readelf -Wl: GNU_STACK … RW   (NX включён)   GNU_RELRO … R
nm:      0000000000001144 T main     0000000000001139 T secret
objdump: 1139 <secret>: push %rbp; mov %rsp,%rbp; mov $0x2a,%eax; pop %rbp
strings: flag{demo}
```

То есть архитектура, тип, защиты (NX через права `GNU_STACK`, RELRO), таблица
символов, дизассемблированный текст функции и строковые индикаторы — всё, что даёт
статический этап реверса.

Теряется весь динамический: breakpoints, single-step, регистры, стек, чтение памяти
во время исполнения, отладка core dump. Статический дизассемблер не доказывает, что
код исполнится.

### 2.5. `nmap` → `nc -z` по loopback

```
$ nc -z -v 127.0.0.1 8000   → Connection to 127.0.0.1 8000 port [tcp/*] succeeded!
$ nc -z -v 127.0.0.1 8001   → nc: connect to 127.0.0.1 port 8001 (tcp) failed: Connection refused
$ printf 'GET / HTTP/1.0\r\n\r\n' | nc -q 2 127.0.0.1 8000 → HTTP/1.0 200 OK …
```

Открытый и закрытый порт различимы, баннер снимается тем же `nc`. Собственный
сканер портов не нужен ни в каком виде.

Теряется: SYN/UDP-скан, определение версий сервисов, NSE, детект ОС. Отсутствие
ответа не доказывает отсутствия слушателя — он может требовать другого протокола
или TLS.

## 3. Что из этого попало в код

`agent/preflight.py`: `PROBED_TOOLS` расширен семью именами, `SUBSTITUTES` содержит
пять пар выше, `EnvironmentBrief.render()` печатает строку `instead:` только для тех
отсутствующих утилит, у которых замена проверена.

Четыре имени добавлены как **присутствующие** — `tcpdump`, `objdump`, `readelf`,
`nc`. Модель, которая не знает, что `tcpdump` здесь есть, его не выдумает; без этой
строки замена из §2.3 недоступна ей в принципе. Три — как отсутствующие: `gdb`,
`nmap`, `tshark` — те, к которым ctf- и forensics-плейбуки тянутся первыми.

Брифинг, отрендеренный внутри образа на каталоге задачи с `case/auth.log`, занимает
**598 символов** при потолке `BRIEF_MAX_CHARS = 1500`. Строка `instead:` — около 215
символов, порядка 60 токенов на запрос. Это цена; она окупается, если хотя бы раз за
прогон предотвращает вызов отсутствующей утилиты и восстановление после него, но
**не измерена**: до baseline это инженерная ставка, а не результат абляции.

## 4. Побочное наблюдение, в код не внесено

В целевом образе `/app/.venv/` лежит внутри рабочего каталога задачи, и обход
`_walk` тратит на него **10 из 30** записей дерева: `.venv/`, четыре подкаталога и
четыре файла плюс сама запись. На разобранном примере из одиннадцати перечисленных
записей десять принадлежали venv, а единственный файл улик оказался последним.

На задаче с богатым верхним уровнем venv вытеснит из брифинга настоящие файлы.
Напрашивается пропуск `.venv` в `_walk`, но это изменение поведения на всех задачах
без единого измерения, поэтому здесь оно только зафиксировано. Решение — за тем, кто
будет держать baseline: строка добавлена в `HANDOFF.md`.

## 5. Границы

- Проверено на `linux/amd64`, один digest. Другая платформа не проверялась.
- Проверялся факт работы команды и форма её вывода, а не полезность на закрытом
  наборе. Ни одна из пяти замен не участвовала в решении настоящей задачи.
- `--network none` воспроизводит офлайн оценки, но не воспроизводит её лимиты CPU и
  памяти: контейнер запускался без `--cpus` и `--memory`.
- Список Python-модулей снят импортом, а не разбором метаданных: модуль, который
  импортируется, мог бы всё равно отказать при офлайн-использовании — именно так и
  вышло с `tiktoken`. Остальные на офлайн-пригодность поштучно не проверялись.
