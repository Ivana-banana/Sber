# AGENTS.md — правила для coding agents

Перед любой работой **полностью прочитать `CLAUDE.md`**: это канонический набор
инженерных правил проекта. Затем открыть `PLAN.md`, `GIT.md` и относящиеся к задаче
документы из `docs/`.

Условия соревнования читать в `docs/task.md`. `Тз сбер.docx` — неизменяемый
первоисточник, распаковывать его при обычной работе не нужно.

Краткий обязательный протокол:

1. Начать с `git status -sb` и проверить, не меняет ли другой участник те же файлы.
2. Для нетривиальной задачи записать цель, проверку и границу работы в `HANDOFF.md`.
3. Сначала получить воспроизводимый baseline, затем менять ровно один фактор.
4. Проверять код реальным запуском; «должно работать» не считается результатом.
5. Не использовать интернет и не добавлять runtime-зависимости в логику агента.
6. Не хардкодить ответы и имена публичных задач; закрытый набор будет другим.
7. Результат прогона записывать в `docs/experiments.md` вместе с commit SHA,
   решёнными задачами, токенами, временем и причиной каждого нуля.
8. Архитектурное решение записывать в `docs/decisions.md` до или вместе с кодом.
9. Не трогать чужие незакоммиченные изменения и не делать побочный рефакторинг.
10. Законченное логическое действие — отдельный коммит по правилам `GIT.md`.

Если правило здесь и в `CLAUDE.md` трактуется по-разному, действует более строгое.
