## Формула победы

Порядок шлюзов нельзя менять:

| Шлюз | Что может обнулить результат | Чем закрывается |
|---|---|---|
| A. Запуск | нет/не executable `run.sh`, ошибка импорта, неверный архив | contract test и smoke из распакованного zip |
| B. Среда | интернет/установка пакетов, несовместимость с образом | offline clean-container gate |
| C. Решаемость | неверный артефакт, timeout, непроверенный ответ | tool loop + внешний verifier + failure taxonomy |
| D. Обобщение | overfit на 7 public cases | capability-oriented design, мутации и новые локальные fixtures |
| E. Эффективность | лишние prompt/tool tokens и wall time | абляции только после сохранения solved count |

Главная метрика — `solved_count`. Вторичные — `total_tokens`, затем `wall_time`.
Public score всегда подписывать как `x/7 public examples`, а не как ожидаемые `x/15`.

## Архитектурная ставка

Начинаем с одного универсального агента с коротким bounded loop:

```text
instruction + workspace
        ↓
cheap inspection → task/capability hypothesis
        ↓
plan next action → local tool → observe compact result
        ↑                         ↓
        └──── recover/replan ← verify
                                  ↓
                               finish
```

Не делаем четыре независимых «агента по типам задач» до данных. Малой LLM нужен
общий надёжный контур, а специализацию сначала задают prompt playbooks и доступные
инструменты. Подробности и открытые решения — `docs/architecture.md`.

## Этапы и Definition of Done

### 0. Bootstrap и контракт — 24 августа

- импортировать публичный repository snapshot отдельным коммитом, записать SHA;
- инвентаризировать `agent/`, семь `local_task/`, тесты и reference solutions;
- проверить фактический вызов Harbor, формат событий и ожидаемый способ завершения;
- зафиксировать digest/пакеты/CLI целевого образа;
- создать builder submission и contract smoke без умной логики.

**DoD:** из чистого checkout одной командой собирается zip ≤10 МБ; после распаковки
его `run.sh` запускается в целевом образе без сети и возвращает контролируемый результат.
Тег `v0.1-contract`.

### 1. Измеримый baseline — 25 августа

- запустить неизменённый example agent на всех public tasks;
- собрать per-task solved, input/output tokens, wall time, число LLM/tool calls;
- классифицировать каждый ноль: startup, timeout, tool, reasoning, verification,
  packaging;
- добиться полного observability без утечки секретов и раздувания контекста;
- выбрать один fix, forensic и CTF/vulnerability case для вертикальных regression tests.

**DoD:** полный baseline воспроизводится одной командой; таблица результатов записана
в `docs/experiments.md`, сырые логи имеют путь/checksum. Тег `v0.2-baseline`.

### 2. Универсальный рабочий контур — 26–27 августа

- компактный system prompt: цель, недоверенные данные, budgets, проверка, stop rules;
- безопасные инструменты: list/read/search, shell, patch/write с exit-code contract;
- итеративная петля с лимитом шагов, deadline и резервом verifier;
- context management: обрезка больших выводов, summaries, защита от повторения;
- capability playbooks без имён public tasks:
  code audit, SWE-style fix, forensic/log analysis, CTF/local-service investigation;
- внешняя проверка результата, а не self-report модели.

**DoD:** baseline не регрессирует; хотя бы одна исходно проваленная capability
закрыта повторяемо или доказано, что example baseline уже закрывает весь public set.

### 3. Обобщение и устойчивость — 28–29 августа

- создать мутации public fixtures: другие имена, пути, значения и формулировки;
- проверить prompt injection из файлов/логов, огромный stdout, tool failure, пустой
  результат, повторяющийся цикл, почти исчерпанный timeout;
- прогнать минимум 3 повтора стохастических случаев;
- добавить fallback для несовместимого tool calling/API поведения модели;
- проверить, что agent не меняет тесты вместо исправления production code;
- полный offline clean-container прогон.

**DoD:** нет известных startup/packaging failures; решаемость стабильна на мутациях;
ограничения честно записаны. Тег `v0.3-robust`.

## Параллельные потоки команды

| Поток | Результат | Граница |
|---|---|---|
| Runtime/pack | образ, `run.sh`, builder, offline gate | не меняет prompt semantics |
| Agent/prompt | loop, budgets, context, playbooks | не подменяет evaluator |
| Tools/security | shell/files/patch, sanitization, exit codes | не хардкодит cases |
| Eval/research | harness, mutations, метрики, failure taxonomy | не чинит код без отдельной задачи |
| Docs/release | decisions, experiments, handoff, checkpoint tags | не заявляет непроверенные числа |

Один файл в момент времени имеет одного владельца. Общие контракты меняются через
короткое решение в `docs/decisions.md` и сообщение в `HANDOFF.md`.

## Риски и планы Б

| Риск | Ранний сигнал | План Б |
|---|---|---|
| Docker/Harbor не поднимается | нет contract smoke 24.08 | отдельный runtime-владелец; локально тестировать `run.sh` с fake endpoint |
| Локальная модель плохо вызывает tools | битый JSON, повтор циклов | текстовый протокол действий + строгий parser/retry с малым budget |
| Token budget неизвестен/разный | прогоны обрываются | динамический budget по deadline, короткий prompt, резерв verifier |
| Overfit на public tasks | ломаются переименованные fixtures | capability mutations и запрет case names в production code/prompt |
| Все нули из-за упаковки | код локально зелёный, archive smoke красный | submission gate на фактически распакованном zip перед каждым tag |
| Сложная архитектура тормозит | много LLM calls без прироста | вернуться к single-loop baseline; усложнения только через абляцию |
| Секреты попали в лог/Git | ключ виден в status/output | redact, rotate key, удалить из текущих файлов; опубликованную историю согласовать отдельно |
